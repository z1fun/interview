# 补充准备｜只准备能讲出来的内容

## 主讲项目：LoveSpouse 数字人（讲 3 分钟）

统一结构：**背景 → 我负责什么 → 一个难点 → 如何处理 → 如何验证**。

已有事实：多角色多语言陪伴系统，支持长期记忆、剧情互动、实时语音、付费媒体解锁。我负责：对话流程（意图识别、场景路由、付费互动推荐、结构化回复）与 Prompt 调优；分层记忆系统（近期对话、会话摘要、长期摘要、稳定事实）；腾讯 IM 对接与消息幂等；Gemini Live 实时语音接入、金币计费、跨实例通话控制。

需要自己回忆的三个点：

1. 一个具体的意图识别/场景路由例子：用户说什么 → 路由到哪个场景 → 回复结构长什么样。
2. IM 幂等的真实实现：幂等键放哪、重复消息如何跳过、唯一约束建在哪。
3. 跨实例通话控制的真实实现：用什么全局标记保证同一用户只有一路通话，异常退出怎么释放。

## 备讲项目（各讲 2 分钟）

- **AI 漏洞研判系统**：LangGraph 多 Agent 工作流（信息完整性评估 → POC 验证 → 定级定价 → 复测），Prompt 设计；FastAPI + PostgreSQL + pgvector 的 RAG 知识库；飞书卡片人工审批。准备一个"为什么用编排而不是单个 Prompt"的回答。
- **POS 数据贯通**：go-zero + gRPC + RabbitMQ + ETCD。准备一个接口适配的字段例子、一个消息消费失败的处理例子。被问微服务时用这个项目。

每个案例追问自己：**为什么这样做？失败怎么办？哪些是我完成的？** 没有测量数据就讲可核实的交付结果。

## 经验边界

- 语音技术：后端管生命周期、计费、路由；编解码/降噪等由模型与 SDK 负责，不冒充音频专家。
- Python/LangGraph 来自漏洞研判项目；主力语言是 Go，LangGraph 不是最熟练的框架——被深问时说清使用范围和理解。
- 陪玩社交场景：可表达对场景的理解（陪伴、互动、付费解锁），但不编造行业数据；把 AI 数字人经验映射到陪玩 Agent（对话、记忆、实时性都是同构问题）。
- “设计思路”用“我会”，“项目题”用“我做过”，两者分清。

## HR：每题准备两句话

- **离职原因**：真实原因 + 求职方向（想继续做 Agent/LLM 应用方向）。
- **工作空档（2026.6 至今）**：如实说明这段时间在做什么（求职/学习/项目），避免含糊。
- **薪资**：岗位 15—25K，准备自己的期望值区间，同时想清楚构成问题（月薪、年终、五险一金基数）。
- **到岗时间**：给出真实日期。
- **为什么选刀锋互娱**：Agent 方向与本人经历匹配 + 产品有真实业务场景（陪玩社交的实时交互）+ 深圳。

## 反问：挑两个

1. 目前 Agent 产品处于什么阶段？后端团队规模和分工是怎样的？
2. 模型是接第三方还是自建？实时语音和流式输出用的什么通道？
3. 入职前三个月最需要交付什么？
4. 陪玩场景里 Agent 目前最大的难点是什么——延迟、成本，还是对话质量？

## 最后 50 分钟

**30 分钟模拟**：介绍 1 分钟 → 数字人项目及追问 9 分钟 → Agent 工程化 8 分钟 → Go/实时通信 6 分钟 → 稳定性 4 分钟 → 反问 2 分钟。

**20 分钟查漏**：只复习刚才卡住的题，再确认面试时间、地点/会议链接、到岗说法。不要继续扩充资料。
