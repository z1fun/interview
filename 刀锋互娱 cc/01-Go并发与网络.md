# Go 并发与网络｜60 分钟

用时：并发 35 分钟，网络与微服务 15 分钟，脱稿复述 10 分钟。

## 1. GMP：调度而非线程

- **G**：goroutine，用户态任务，初始栈小（约 2KB），可动态增长，创建成本远低于线程。
- **M**：操作系统线程，真正执行代码。
- **P**：执行 Go 代码所需的调度资源，持有本地运行队列；数量由 `GOMAXPROCS` 决定，默认等于 CPU 核数。

关键结论：goroutine 便宜但**并非无限**——数据库连接、下游 QPS、内存是有限的，所以仍要限并发。阻塞系统调用会挂起 M，网络 I/O 由 runtime 的 netpoller（epoll）接管，M 不会被连接读写占死，所以 goroutine-per-conn 模型可行。

## 2. 并发首先保护资源

无限并发只会把压力变成排队、内存增长和超时。做法：

1. 固定 worker 数或信号量限制执行数量（如 `make(chan struct{}, n)`），也可用 `errgroup` + `SetLimit`。
2. 同时限制等待队列：排队超时或队列满就拒绝、转异步。
3. 并发上限结合数据库连接池和压测确定。

**易错点**：先启动无限 goroutine 再让它们等信号量，goroutine 仍然堆积，限不住资源。

## 3. context：取消与超时的传播

- `WithTimeout`/`WithDeadline` 控制超时，`WithCancel` 手动取消，`WithValue` 只传请求元数据（traceID 等），不传业务参数。
- 请求的 ctx 继续传给数据库、HTTP、RPC 调用；派生超时后 `defer cancel()` 及时释放计时器。
- **取消不是强杀**：被调方必须 select `ctx.Done()` 响应，网络和 DB 调用天然响应 ctx。

## 4. goroutine 泄漏

常见原因：channel 阻塞收发无人接收、持锁等待、无退出条件的后台循环、WaitGroup 使用错误。

- 排查：pprof goroutine profile 看数量趋势和堆栈，找无法结束的收发/等待；线上看 `runtime.NumGoroutine` 指标趋势。
- 预防：select 加 `ctx.Done()` 或超时退出路径；channel 由明确所有者关闭（通常发送方在所有发送结束后关闭）。

## 5. 同步原语速查

| 手段 | 用途 | 易错点 |
|---|---|---|
| Mutex | 保护共享状态 | 持锁期间做慢 I/O 放大等待 |
| channel | 任务/结果交接 | 没人接收时一直阻塞；重复关闭 panic |
| WaitGroup | 等待一组任务结束 | 本身不传错误、不取消任务 |
| atomic | 计数器、标志位 | 只保证原子性，不解决逻辑上的复合操作 |
| sync.Once | 只执行一次 | 初始化失败不会重试 |
| sync.Pool | 复用临时对象 | 池内对象随时可能被清空 |

基础追问：普通 map 并发读写需要同步（或 `sync.Map`）；接口包含动态类型和值，装入 nil 指针后接口本身不等于 nil。

## 6. 网络与连接

- **netpoller**：一个 goroutine 阻塞读一个连接，epoll 通知就绪，线程不被占死——这是 Go 长连接的基础。
- **sql.DB 连接池**：`SetMaxOpenConns`（上限）、`SetMaxIdleConns`、`SetConnMaxLifetime`（超龄重建）；池耗尽表现为请求排队超时，与并发控制联动。
- **http.Client**：Transport 复用连接，**响应体必须读完并 Close 才能复用**；设置整体超时 `http.Client{Timeout}`。
- **http.Server**：设置 `ReadHeaderTimeout`（防慢速攻击）、`ReadTimeout`、`WriteTimeout`、`IdleTimeout`。
- 接口返回 err 时调用方不要泄露 body；超时后旧请求仍在执行，注意重复副作用（关联幂等）。

## 7. 微服务与 RPC（POS 数据贯通佐证）

- **go-zero**：api（HTTP 网关层）+ rpc（gRPC 服务）+ etcd 服务发现 + 中间件 + breaker 熔断。被问到微服务时讲 POS 数据贯通里自己的真实职责（接口适配、消息消费加工），框架特性说清楚即可。
- **gRPC 四种调用**：一元、服务端流、客户端流、**双向流**——双向流是实时语音这类场景的载体，可与 Gemini Live 呼应。
- RPC 要设超时；重试只在幂等操作上做（与 04 篇幂等联动）。
- 服务拆分按业务域，接口边界清晰、数据库隔离，跨服务查询评估冗余/聚合而非随意 JOIN。
