# 实时通信｜45 分钟

用时：长连接 20 分钟，多实例与语音 15 分钟，脱稿复述 10 分钟。岗位是陪玩社交 AI 产品，实时交互是核心，数字人项目是直接经验。

## 1. WebSocket 基础

- HTTP Upgrade 握手（101）后升级为全双工长连接；对比：HTTP 轮询浪费请求、SSE 单向、WebSocket 双向。
- **心跳保活**：应用层 ping/pong，服务端读超时（如 2 个心跳周期没消息就断），清理僵尸连接；中间网关（Nginx 等）也有读超时，心跳间隔要小于它。
- **断线重连**：客户端指数退避重连（1s→2s→4s 封顶），重连后恢复会话：要么服务端补发离线消息，要么客户端拉历史对齐。
- **连接容量**：单机连接数受文件描述符、内存、带宽限制，调 ulimit 与内核参数；Go 的 netpoller 让一连接一 goroutine 可行（呼应 01 篇）。
- 库：gorilla/websocket 或 nhooyr.io/websocket；连接上通常一读一写两个 goroutine，写用带缓冲 channel 串行化。

## 2. 多实例：连接分布与消息路由

连接存在实例内存里，扩容后“谁连着谁”成了问题。两种做法：

1. **固定实例**：按用户 ID 一致性哈希把连接绑定到实例，同用户消息总能找到，但实例故障要整体迁移。
2. **任意连接 + 路由**：实例间用 Redis Pub/Sub 或 MQ 广播/定向投递，目标实例本地匹配连接后下发。

**跨实例调用控制（数字人真实经验）**：同一用户只能有一路通话——用一个全局标记（Redis 锁/DB 唯一约束）做通话唯一性控制，任何实例创建通话前先抢占标记，避免双实例各自放行。

**状态外置**：会话状态放 Redis/DB 而非实例内存，实例挂了重连能恢复；内存只留连接本身。

## 3. IM 对接（LoveSpouse 真实经验）

- 三方 IM（腾讯 IM）负责底层消息通道与离线存储，我们消费其消息流做业务处理。
- **幂等**：IM 可能重复推送，以消息 ID 做幂等键，DB 唯一约束兜底，重复消息安全跳过（04 篇展开）。
- **顺序**：按消息序列号处理，乱序时重排或按业务容忍丢弃过期消息。

## 4. 实时语音（Gemini Live）

- Gemini Live 是 WebSocket 双向流：音频上行 → 模型 → 音频下行，与 gRPC 双向流同构（呼应 01 篇）。
- **后端职责**：会话创建与状态机（空闲/连接中/通话中/结束）、超时挂断、**金币计费**（按时长扣费、余额不足中断）、**跨实例唯一通话控制**。
- 音频编解码、降噪、打断检测由模型/SDK/客户端处理——面试时讲清楚自己负责的边界，不冒充音频专家。
- 计费与模型成本对齐：业务收入（金币）要覆盖模型调用成本，断线、异常通话要能正确结算。

## 5. 背压与积压

- 下游（客户端）消费慢时，写缓冲堆积：设写超时，超时主动断开，防止内存被打爆。
- 消息积压：消费速度跟不上时告警、扩容消费者、必要时限制生产。
