# 面试问答｜18 道核心题

每题按“结论 → 做法 → 一个边界”回答，控制在 30—60 秒。标注“真实项目”的题用简历中的实际实现回答；其余是设计思路，技术方案不代表个人已做过的项目。

## Go 与并发

### 1. GMP 调度模型是什么？

goroutine 是用户态任务，M 是线程，P 是执行 Go 代码所需的调度资源，GOMAXPROCS 决定 P 数量。goroutine 创建成本低，但数据库连接和内存有限，业务上仍要限并发。网络 I/O 由 netpoller 接管，阻塞读不占死线程，所以长连接场景一连接一 goroutine 可行。

### 2. goroutine 泄漏怎么排查和预防？

症状是 goroutine 数量持续增长。用 pprof goroutine profile 看堆栈，找无法结束的收发、等待或后台循环。预防：select 加 ctx.Done() 或超时退出路径；channel 由明确所有者关闭。边界：context 取消是协作信号，代码不响应就无效。

### 3. context 的使用规则？

WithTimeout/WithCancel 控制超时和取消，请求 ctx 传给 DB、HTTP、RPC 调用；派生超时后 defer cancel() 释放资源；WithValue 只放 traceID 这类元数据。边界：取消不是强杀 goroutine。

### 4. channel 和锁怎么选？

channel 用于任务与结果的交接，锁保护共享状态。规则：channel 由发送方关闭，重复关闭 panic；锁内避免慢 I/O。边界：接口装 nil 指针后接口本身不为 nil；普通 map 并发读写要同步。

## Agent 与 LLM

### 5. 流式输出怎么实现？

后端用 SSE 逐 chunk 下发，客户端增量渲染；Nginx 等代理要关缓冲（X-Accel-Buffering: no），否则退化成一次性返回。指标分 TTFT 和生成速率看。边界：SSE 单向，双向实时交互（语音）要用 WebSocket。

### 6. 工具调用一个回合的流程？

模型输出结构化调用（工具名 + JSON 参数）→ 服务端白名单校验后执行 → 结果回填消息 → 模型继续生成。要限制最大轮数，工具失败把错误回传让模型修正。边界：支付、删除类操作要人工确认。

### 7. 长对话上下文怎么管理？

窗口有限、按 token 计费，不能无限堆历史。组合用：滑动窗口保留最近原文、超窗部分压成摘要、用户档案类稳定事实独立存储按需注入。边界：摘要丢细节，稳定事实要可更新。

### 8. 分层记忆怎么设计？（真实项目）

数字人项目里分四层：近期对话原文、会话摘要、跨会话长期摘要、稳定事实。摘要会话结束后异步生成，不阻塞回复；组装 prompt 时按相关性选取。边界：摘要必然有损，事实层要支持纠错更新。

### 9. 模型调用成本怎么优化？

模型分级（意图/分类用小模型，生成用大模型）、摘要压缩输入 token、结果缓存、非关键链路异步化、按 token 计量并让业务计费与模型成本对齐。边界：省成本不能牺牲核心体验，例如对话质量。

## 实时通信

### 10. WebSocket 和 SSE 怎么选？

单向文本流用 SSE，简单；双向实时交互用 WebSocket。长连接靠应用层心跳保活，服务端读超时清理僵尸连接；断线指数退避重连并恢复会话。边界：单机连接数受文件描述符、内存限制。

### 11. 多实例下消息怎么路由到正确实例？

两种：按用户 ID 一致性哈希把连接绑定到固定实例；或实例间用 Redis Pub/Sub 或 MQ 路由，目标实例本地匹配连接后下发。会话状态放 Redis/DB，实例挂了重连可恢复。边界：内存只留连接，状态外置。

### 12. 实时语音的通话控制和计费怎么做？（真实项目）

Gemini Live 是 WebSocket 双向流。后端负责会话状态机、超时挂断、按通话时长扣金币、余额不足中断；用全局唯一标记（Redis/DB 唯一约束）保证跨实例同一用户只有一路通话。边界：音频编解码由模型/SDK 处理，后端管生命周期与计费。

## 缓存、消息与数据

### 13. 缓存穿透、击穿、雪崩分别怎么处理？

穿透是不存在的数据反复回源，参数校验 + 短暂缓存空结果；击穿是热点 key 失效大量回源，互斥重建或限制回源并发；雪崩是大批 key 同时失效，TTL 抖动 + 限流降级。更新走先写 DB 再失效缓存，失败重试，TTL 兜底。

### 14. 分布式锁怎么实现？边界在哪？

SET NX + 唯一持有者 + 过期时间；释放用 Lua 原子比较持有者再删。边界：任务执行超过锁 TTL 时锁可能被抢走，用续期或把关键写入做成幂等兜底。

### 15. 消息重复消费怎么办？（真实项目）

IM 会重复推送。以消息 ID 做幂等键，数据库唯一约束兜底，幂等记录与业务变更同一事务提交；提交后 ACK，重投时安全跳过。乱序按序列号判断丢弃旧消息。

### 16. 慢查询怎么排查？

定位慢 SQL → EXPLAIN 看扫描类型和行数 → 按最左前缀设计联合索引或改写 SQL → 对比正确性与性能。边界：不是所有查询都该走索引，大范围聚合可能全扫更快。

## 稳定性

### 17. 压测怎么做？

先定指标（QPS、P99、错误率），压测环境隔离生产，阶梯加压找拐点，观察 CPU、GC、连接池、数据库和下游耗时。边界：压测结果要结合线上真实流量校准。

### 18. 线上响应变慢怎么排查？

先确认影响面与时间点，看最近发布变更，再看监控（资源、错误率、下游、积压），按链路逐层拆到具体组件，必要时回滚或限流止损。边界：先止损再找根因。
