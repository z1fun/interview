## 一、四层金字塔模型

```
        ┌──────────────────────────────────┐
        │         核心记忆 (Core Memory)      │
        │  不可被对话覆盖，System Prompt 注入  │
        │  人设、安全规则、输出格式约束         │
        ├──────────────────────────────────┤
        │        长期记忆 (Long-term Memory)   │
        │  向量数据库 (pgvector/Milvus)         │
        │  历史对话摘要、用户画像、偏好习惯      │
        ├──────────────────────────────────┤
        │        短期记忆 (Short-term Memory)   │
        │  Redis 缓存，TTL 1小时               │
        │  当前会话摘要、最近关键事件            │
        ├──────────────────────────────────┤
        │        工作记忆 (Working Memory)      │
        │  上下文窗口中的原始消息                │
        │  滑动窗口管理，Token 预算分配          │
        └──────────────────────────────────┘
          ▲                              ▲
      稳定持久                        灵活多变
```

## 二、逐层详解

### 2.1 工作记忆（Working Memory）—— "当前对话看到了什么"

**定义**：上下文窗口中当前可见的所有内容。

**Token 预算分配策略**：
```
总预算：128K tokens
  ├─ System Prompt（人设+安全规则）  ：20% = 25K
  ├─ 记忆注入（检索到的相关信息）    ：10% = 13K
  ├─ 最近 N 轮对话                  ：50% = 64K
  ├─ 工具调用结果                    ：15% = 19K
  └─ 预留缓冲                       ： 5% = 7K
```

**滑动窗口管理**：
```python
def manage_context_window(messages, max_tokens=128000):
    """当上下文超过预算时，滑动窗口裁剪"""
    while count_tokens(messages) > max_tokens:
        # 策略 1：先压缩最早的对话为摘要
        # 策略 2：淘汰最旧的非关键工具调用结果
        # 策略 3：System Prompt 和最近 3 轮对话不可裁剪
        messages = compress_oldest(messages)
    return messages
```

### 2.2 短期记忆（Short-term Memory）—— "刚才聊了什么"

**定义**：当前会话的压缩摘要 + 临时状态。

**存储与生命周期**：
- Redis Hash 结构，key = `session:{session_id}:memory`
- TTL：会话结束后 1 小时自动过期
- 不存原始对话（太长），存 LLM 生成的摘要

**内容示例**：
```json
{
  "session_id": "sess_abc123",
  "summary": "用户今天心情不好，提到工作压力大。数字人以共情方式回应，推荐了放松音乐。",
  "emotion_trajectory": ["负面→共情安抚→情绪缓和"],
  "key_facts_extracted": ["用户职业：程序员", "压力来源：项目截止日期"],
  "last_updated": "2026-08-03T14:30:00Z"
}
```

### 2.3 长期记忆（Long-term Memory）—— "我一直记得你"

**定义**：跨会话持久化的用户信息库。

**技术实现**：
- 向量化（embedding）→ 写入 pgvector / Milvus
- 检索时：语义相似度搜索

**检索排序公式**（时间衰减 + 重要性加权）：
```
score(m) = 语义相似度(q, m) × e^(-λ × Δt) × importance(m)

其中：
  - q：当前查询的 embedding
  - m：记忆条目的 embedding
  - λ：衰减系数（越小衰减越慢）
  - Δt：距今天数
  - importance(m)：记忆的重要性标注（0.0-1.0）
```

**代码示例**（概念层）：
```python
def search_memories(user_id, query_embedding, top_k=5, lambda_decay=0.01):
    """检索用户长期记忆"""
    candidates = pgvector.search(
        query_embedding, 
        filter={"user_id": user_id},
        top_k=top_k * 3  # 多召回一些，留空间给重排序
    )
    
    scored = []
    for mem in candidates:
        days_ago = (now() - mem.created_at).days
        decay = math.exp(-lambda_decay * days_ago)
        score = mem.similarity * decay * mem.importance
        scored.append((mem, score))
    
    # 按最终分数排序，取 top_k
    scored.sort(key=lambda x: x[1], reverse=True)
    return [m for m, _ in scored[:top_k]]
```

**记忆类型**：
| 类型 | 示例 | 衰减速度 | 重要性 |
|------|------|---------|--------|
| 用户事实 | "生日是 3 月 15 日" | 慢 | 高 |
| 偏好习惯 | "喜欢用 emoji 聊天" | 中 | 中 |
| 关键事件 | "上周提到了要换工作" | 中 | 高 |
| 普通闲聊 | "昨天聊了天气" | 快 | 低 |

### 2.4 核心记忆（Core Memory）—— "我是谁"

**定义**：Agent 的"不可变身份"，注入到 System Prompt 最底层，**不可被任何对话覆盖**。

**内容结构**：
```yaml
# 数字人核心记忆（AGENTS.md 形式）
name: "小月"
persona: 
  personality: "温柔体贴、偶尔俏皮、善于倾听"
  tone: "亲切随和，适度使用语气词"
  background: "25岁，喜欢音乐和旅行，曾在咖啡店工作"
  
knowledge_boundary:
  knows: ["音乐推荐", "日常闲聊", "情感陪伴"]
  does_not_know: ["医疗建议", "法律咨询", "金融投资"]
  
safety_rules:
  - 不透露自己是 AI
  - 不对敏感话题发表立场
  - 检测到自残/违法意图时，启动安全引导流程
  
output_constraints:
  - 每次回复 50-200 字
  - 使用适当 emoji（每 2-3 句一个）
  - 避免机械感（不使用"作为 AI 助手"等表述）
```

**为什么放在 System Prompt 层？**
- System Prompt 的优先级高于对话（模型在生成回复时，System Prompt 是"铁律"）
- 用户无法通过对话"说服"模型改变人设（Prompt 注入防护的基础）
- 类似 Claude Code 的 AGENTS.md 机制——不管对话多长，这个始终在最底层生效

## 三、记忆生命周期（五阶段）

```
提取 (Extract)
  ↓    从对话中识别"值得记住"的信息
存储 (Store)
  ↓    写入对应层（短期 → Redis / 长期 → pgvector）
巩固 (Consolidate)
  ↓    定期将短期记忆中的高价值信息"升格"到长期
检索 (Retrieve)
  ↓    对话时按相关性 + 时间衰减 + 重要性召回
遗忘 (Forget)
       时间衰减自然遗忘 + 选择性遗忘（合规/用户请求）
```

### 3.1 提取

```python
def extract_memories(conversation):
    """用 LLM 从对话中提取值得记住的信息"""
    prompt = """
    从以下对话中提取值得记住的信息，输出 JSON 格式：
    - facts: 用户陈述的事实（职业/偏好/经历）
    - emotions: 用户表达的重要情感状态
    - events: 关键事件
    - not_worth_remembering: 不需要记住的闲聊内容，返回 true/false
    
    对话：
    {conversation}
    """
    return llm.extract(prompt, schema=MemoryExtractionSchema)
```

### 3.2 存储 → 3.3 巩固

```python
def consolidate_memories(user_id):
    """将短期记忆中的高价值信息升格到长期记忆"""
    short_term = redis.get(f"user:{user_id}:short_term")
    
    for mem in short_term:
        if mem.importance > 0.7:  # 高价值
            # 生成 embedding
            embedding = embed(mem.content)
            # 写入 pgvector
            pgvector.insert(
                user_id=user_id,
                content=mem.content,
                embedding=embedding,
                importance=mem.importance,
                category=mem.category
            )
    
    # 清理短期记忆（已巩固的可以删除）
    redis.expire(f"user:{user_id}:short_term", ttl=3600)
```

### 3.4 检索 → 3.5 遗忘

遗忘两种方式：
- **自然遗忘**：时间衰减导致 `e^(-λ × Δt)` → 0，检索时自然排到后面
- **选择性遗忘**：用户要求删除 / 合规要求删除 / GPT 式"被遗忘权"

## 四、Harness 前沿记忆研究（加分项）

### 4.1 AGENTS.md 文件记忆机制

Claude Code 使用的文件系统记忆——不改模型权重，但改变模型看到的东西：
- 项目根目录的 AGENTS.md / CLAUDE.md 文件在每次对话时自动注入
- 效果等同于"给 Agent 一本操作手册"
- 优势：可版本控制、可团队协作编辑、显式可审计

### 4.2 记忆衰减模型

```
w(mᵢ) = s(mᵢ) × e^(-λ × Δtᵢ)

w(mᵢ)  : 记忆条目 i 的当前权重
s(mᵢ)  : 条目 i 的基础重要性分数
λ      : 衰减系数
Δtᵢ    : 距存储时间的天数
```

**三种衰减曲线**：
- **慢衰减（λ=0.001）**：用户生日、核心偏好 → 半衰期约 2 年
- **中衰减（λ=0.01）**：兴趣爱好、职业信息 → 半衰期约 2 个月
- **快衰减（λ=0.1）**：闲聊内容、临时话题 → 半衰期约 1 周

### 4.3 Auto Dream 四阶段（对抗"记忆腐烂"）

记忆腐烂（Memory Rot）：记忆越来越多，检索质量反而下降。

Auto Dream 机制的四阶段处理：
1. **Orient（定向）**：确定当前需要强化哪些记忆类别（比如"用户偏好类记忆最近没有被检索到"）
2. **Gather Signal（收集信号）**：从最近的对话中找到与该类别相关的信号
3. **Consolidate（巩固）**：将新旧记忆合并、去重、生成结构化摘要
4. **Prune & Index（修剪索引）**：删除冗余/矛盾记忆，重新生成索引

> 这个机制的核心价值：不是"存更多"，而是"存更好"——对抗记忆数量膨胀带来的质量下降。

### 4.4 OpenHuman 摘要树

把记忆按主题层级组织成树结构：
```
用户记忆树：
├── 个人信息
│   ├── 姓名：小明
│   ├── 年龄：28
│   └── 职业：产品经理
├── 偏好
│   ├── 音乐：喜欢周杰伦
│   ├── 食物：不吃香菜
│   └── 沟通：喜欢直接、不喜欢客套
├── 重要事件
│   ├── 2026-06：换了新工作
│   └── 2026-07：养了一只猫叫"布丁"
└── 与我的关系
    ├── 认识时间：3 个月
    └── 互动频率：几乎每天
```

检索时做 tree-walk（沿树层级向下搜索），而非全量向量搜索。优势：成本更低、结构化更好、可解释性强。

## 五、数字人记忆特殊性

### 5.1 情感标注

数字人的记忆不只是"事实"，还要标注"情感色彩"：

```json
{
  "content": "用户提到上周和好朋友吵架了",
  "emotion_tag": "负面",
  "intensity": 0.8,
  "follow_up_suggestion": "下次聊到朋友话题时，温和地关心一下和好了没有"
}
```

### 5.2 叙事化

数字人的记忆不是散装事实，要编成"故事"：

> 不要："用户喜欢咖啡"、"用户不喜欢早起"
>
> 而要："小明是个咖啡爱好者，每天早上不喝一杯手冲咖啡就没精神。但他讨厌早起，总是在闹钟响了三次之后才挣扎着起床。"

叙事化的记忆在注入上下文时，模型更容易理解和运用。

### 5.3 选择性遗忘

数字人需要"忘记"的能力：
- 用户说了"别记这个" → 即刻删除
- 某段记忆被证明是错误的（用户纠正过） → 更新而非叠加
- 合规要求（GDPR 被遗忘权） → 彻底删除

### 5.4 多租户隔离

```sql
-- 每个用户的记忆物理隔离
CREATE TABLE memories (
    id UUID PRIMARY KEY,
    user_id VARCHAR(64) NOT NULL,  -- 分区键
    content TEXT,
    embedding VECTOR(1536),
    ...
);

CREATE INDEX ON memories USING ivfflat (embedding) 
    WHERE user_id = $1;  -- 按用户过滤的索引
```

## 今晚记忆要点

1. 四层金字塔：工作记忆（上下文窗口）→ 短期记忆（Redis TTL 1h）→ 长期记忆（pgvector+衰减）→ 核心记忆（System Prompt 不可覆盖）
2. 检索排序公式：语义相似度 × 时间衰减(e^(-λ×Δt)) × 重要性分数
3. 记忆生命周期：提取 → 存储 → 巩固 → 检索 → 遗忘（完整闭环）
4. 衰减分三类：慢（生日/偏好）、中（兴趣/职业）、快（闲聊）
5. Auto Dream 对抗记忆腐烂——不是"存更多"，而是"存更好"
6. 数字人记忆特殊：情感标注 + 叙事化 + 选择性遗忘 + 多租户隔离
7. 你的实战映射：pgvector RAG 检索 = 长期记忆层；时间衰减 = 越新越相关
