| 🥉 | **商云串口 + POS 微服务** | **串口通信**（粘包/重连/协议适配）→ 对口「设备接入」「嵌入式联调」；**go-zero + gRPC + ETCD + RabbitMQ** → 对口加分项第 2 条 |

**LoveSpouse 三个难点（必被追问）**：
1. **分层记忆**：四层各自的生成时机 + Token 预算分配。**稳定事实走结构化抽取，不走摘要**（怕摘要漂移）。
2. **跨实例通话**：Redis + **SETNX 抢占** + TTL 兜底故障释放。**脑裂靠"写状态时校验持有者标识"防**。
3. **计费幂等**：预扣 → 心跳累加 → 最终结算；**唯一业务 ID + 唯一索引**；每日对账兜底。

**AI 漏洞研判三个难点**：
1. **为什么用 LangGraph**：状态图 + checkpointer（审批要挂几小时）+ 原生 human-in-the-loop。**缺点也要说**：抽象厚、版本有破坏性变更、简单流程不如自己写。
2. **RAG**：语义切分 → pgvector 向量召回 → **关键词混合检索**（纯向量对漏洞编号召回差）→ Rerank → Prompt 要求引用。
3. **防幻觉**：输入侧 Prompt 约束 + 输出侧 schema 校验 + **关键结论走人工审批**。**「不指望 Prompt 消除幻觉，要在流程设计上让人兜住。」**

## ⚡ 技术速答：抓这五个词 ⭐

> JD 职责第 2 条原文：**「鉴权、限流、重试、结果落库与服务封装」** —— 背下来。

**① 鉴权**：Key 不硬编码、**不落日志**（日志中间件对 Authorization 脱敏）、多租户多 Key、统一 Client 出口。
**② 限流**：三层 —— 自保并发（信号量）｜**上游 429 退避重试 + 反馈降速**｜业务侧按租户配额。Redis 分布式限流 + **本地兜底（Redis 挂了不能全失效）**。
**③ 重试**：**可重试** 网络超时/5xx/429；**不可重试** 400/401/**内容审核拒绝**。指数退避 + 抖动，2-3 次。**流式特殊**：首包前可透明重试，**首包后不能重试**（会重复推内容）。
**④ 结果落库**：记录租户/模型/Prompt 版本/Token/耗时/状态 → 成本核算 + 排查 + 效果对比。**异步写 + 脱敏**。
**⑤ 服务封装** ⭐：**统一 `LLMProvider` 接口**（Chat / ChatStream），换模型不改业务；之上包一层横切能力（限流/重试/超时/日志/计费/降级）；**降级要带开关**。

**Prompt 编排（JD 职责第 3 条）**：
- **上下文管理**：按 Token 预算分配；优先级 **稳定事实 > 系统提示 > 近期对话 > 长期摘要**；**Token 是估算的，留 10-20% 余量**。
- **工具调用**：模型给的参数**必须校验**（当外部输入）；执行幂等 + 超时；**轮次上限防死循环**；工具列表按权限动态生成。
- **结构化输出**：JSON Schema 约束；**容错解析**（剥代码块、提取首个完整 JSON）；失败重试一次，再失败走默认分支，**绝不抛异常给用户**。
- **流式**：SSE + **主动 flush**（否则被缓冲住等于不流式）；**Nginx 要关 buffering**；监听 `ctx.Done()` **及时取消上游，不然白烧 Token**；要有明确结束事件。

**多模态 / 检测模型（对口宠智灵）**：
- 和文本 LLM 不同 —— **图片先传对象存储给 URL**；**检测是异步的**：提交任务 → task_id → **回调 / 轮询**。
- 后端要处理：**回调幂等**（重复/乱序）、任务状态机、**超时兜底**（回调可能永远不来）、结果结构化落库。
- 检测 + LLM 配合：**检测模型出结构化结果 → 喂给 LLM 生成建议**，职责清晰成本低。

**私有化部署（JD 第 6 条）**：
- **Ollama** 开发/小规模，部署简单性能一般｜**vLLM** 生产主流｜**内网网关**统一出口（one-api / new-api）
- **vLLM 为什么快**：**PagedAttention**（KV Cache 分页按需分配，显存利用率高）＋ **连续批处理**（每生成一个 token 重组批，完成的立刻退出）
- 选型看：**合规 / 成本 / 延迟 / 运维成本 / 模型能力**。**「先用 API 验证业务，量起来或有合规要求再私有化。」**

## 🕳️ 四个缺口（三句话：承认 + 理解 + 替代）

| 缺口 | 一句话答法 |
| --- | --- |
| **Kafka** | 「生产用 RabbitMQ 做过 POS 数据消费和幂等。Kafka 核心是**分区 + 消费组**，partition 内有序，**offset 可重置所以能重放**。跟 RabbitMQ 最大区别是分布式日志模型，吞吐高得多。」 |
| **爬虫** | 「没生产经验。核心问题是**调度 / 去重（布隆过滤器）/ 限速反爬（代理池、UA 轮换）/ 增量 / 解析存储分离**。分布式一般用 Redis 做队列和去重，或 Scrapy-Redis。**让我设计我能给方案。**」 |
| **vLLM** | 「没落地过，我们走 API。**PagedAttention + 连续批处理**是核心，开发和验证用 Ollama 最省事，生产 vLLM 主流。」 |
| **MQTT** | 「没用过。IoT 用长连接发布订阅因为设备多、功耗低。**QoS 1 可能重复所以消费侧必须幂等**；**离线检测靠遗嘱消息 + 心跳超时**。」 |
