**怎么理解这件事：**

- **所以这是一次「练手 / 保底 / 探行情」性质的面试。** 心态放轻松：你没有心理负担，反而是你挑他们。
- **但仍然值得认真准备**，原因见下一节——这家公司的业务方向，恰好是你想转型的「AI 应用后端」，**而你的简历匹配度高得意外**。

**建议口径**（见 [03 篇](03_岗位解读_薪资谈判_反问.md)）：

### 1.2 这家公司到底做什么（决定了你会被问什么）

> 资料来自公开工商与媒体信息，**面试时请以对方口径为准**。

集团成立于 2022 年（前身 2014 年的深圳市索未来科技有限公司），**天使轮，20-99 人**，龙岗。三大业务线：

| 业务线 | 是什么 | JD 里的影子 |
| --- | --- | --- |
| **① AI 数字人 Agent 一站式 SaaS** | 旗下「智企未来」出品。交互数字人 + 大模型 + 智能体，支持形象定制、低代码编排、一键发布。用于**酒店、展厅、学校** | 「大模型对接」「Prompt 编排」「**设备接入**」（展厅一体机/大屏） |
| **② 一体化 AI 数智职教** | 面向中职：教学实训平台、AI 课程、**智能实训沙盘**、**具身机器人**、数字人 | 「**设备接入**」「与**嵌入式**联调」「任务调度」 |
| **③ 宠智灵 / Petdot** | AI 宠物健康管理 APP：智能问诊、健康测评、**AI 品种识别**、AI 多模态视觉识别 | 「**多模态 / 检测模型 API**」「分布式爬虫」（知识库采集） |

**三个关键推论：**

1. **「多模态 / 检测模型」= 宠物视觉识别（品种、皮肤、口腔）+ 职教实训画面检测。** 这类模型 API 的特征是**图片上传 → 异步回调 → 结果落库**，和纯文本 LLM 调用不同（见 [04 篇](04_大模型API对接与Prompt编排.md)）。
2. **「设备接入」= 智能硬件 + 展厅大屏 + 具身机器人。** 要的是 **MQTT / WebSocket 长连接 / 串口** 这一套 —— **你的商云前台串口通信、路由器 Portal 认证经验在这里直接能用**。
3. **「分布式爬虫」（职位标签里有，JD 正文却没提）** —— 大概率是给知识库/题库做数据采集。**这是你简历上唯一的真空区**，必须提前准备一套说法（见 [07 篇](07_分布式爬虫与设备接入.md)）。

### 1.3 🎯 你的三张牌（按威力排序，这次排序和以往不同）

**🥇 第一张牌：LoveSpouse 数字人 —— 你做过他们正在卖的东西**

这是本场最大的惊喜。他们在卖「**AI 数字人 Agent 一站式 SaaS**」，而你独立负责过：
- 多角色、多语言对话 + **长期记忆**（近期对话 / 会话摘要 / 长期摘要 / 稳定事实）
- **实时语音**（Gemini Live）+ 金币计费 + 跨实例通话控制
- 意图识别 → 场景路由 → 付费推荐 → 结构化回复的**编排链路**
- 腾讯 IM 接入 + **幂等处理**

> **讲法**：「我做过一个数字人陪伴产品，从对话编排、分层记忆到实时语音全链路。看到咱们的 AI 数字人 SaaS，我觉得业务形态很像，我的经验可以直接迁移。」

**🥈 第二张牌：AI 漏洞研判系统 —— 证明你能驾驭 Prompt 编排与多 Agent**

JD 只要求「Prompt 工程要点」（角色设定 / Few-shot / 结构化输出 / 流式），**你做的是 LangGraph 多 Agent 工作流 + pgvector RAG**——**超出要求一个层级**。JD 加分项第 4 条「RAG、向量检索、Agent / Function Calling 落地经验」，你**直接命中**。

> 这张牌的用法是**降维打击**：不要一上来就讲 LangGraph，先按 JD 的语言讲 Prompt 工程，再"顺带"提到你是用 LangGraph 编排的。

**🥉 第三张牌：商云前台 + POS 数据贯通 —— 技术栈匹配度最高**

- 商云前台：**串口通信**（设备接入！）、AES/RSA **加解密**、RabbitMQ、SQLite+云同步、Wails 桌面端 → 对应「**与嵌入式联调**」「设备接入」
- POS 数据贯通：**go-zero + gRPC + Protobuf + ETCD + RabbitMQ + Docker** → JD 第 2 条明写 go-zero，加分项第 2 条 gRPC/微服务**全中**

> **两张牌一句话总结**：**「数字人 + 多 Agent」证明你会用 AI，「串口 + 微服务」证明你能接设备、能扛架构。**

### 1.5 ⚠️ 两个需要留意的点

**疑点一：职位标签与 JD 正文不匹配**

标签里有「**分布式爬虫**」「**系统架构设计经验**」，但 JD 正文的六条职责里**一个字都没提爬虫和架构设计**，全是「API 对接、Prompt 编排、部署运维」。
→ **推测**：这是一个**复用了公司其他岗位模板**的 JD，或者团队里确实有数据采集的活没人干。
→ **应对**：反问环节直接确认 —— **「职位标签里有分布式爬虫，咱们这边的数据采集是自建还是用三方？目前是哪个团队在做？」** 这个问题问出来，既显得你仔细读了 JD，又能探到真实工作内容。

**疑点二：这套技术栈像是「一个后端扛全部」**

JD 同时要求：AI 模型对接 + Prompt 编排 + Docker 运维 + 缓存队列降级 + 和前端/算法/嵌入式三方联调。
→ **含义**：AI 方向的后端团队大概率 **1-3 人**，你要从接口写到部署。**这既是机会（成长快、话语权大）也是风险（杂活多、无 mentor）**，面试时可以问「团队现在几个人，怎么分工」。

## 五、三个一定要做 / 三个绝对不要做

**一定要做：**
1. ✅ **开场就把「数字人」抛出去** —— 这是你和这家公司业务的重合点，能让面试官立刻觉得"这人不用教"。
2. ✅ **主动划边界** —— 「Kafka 我没在生产用过，但我用 RabbitMQ 做过消息幂等，两者的模型差异我理解」。比硬吹可信十倍。
3. ✅ **讲方案而不只是概念** —— JD 第 2 条要的是"服务封装"能力。每讲一个 API 对接的坑，都接一句「**在我的项目里我会这么封装……**」。

**绝对不要做：**
1. ❌ **不要因为薪资低就敷衍** —— 这家公司的业务方向和你想转的 AI 应用后端高度一致，**就算不来，这套话术也能复用**。
2. ❌ **不要吹「精通 Kafka」「精通 K8s」** —— 标签里有 Kafka，追问两层就崩。
3. ❌ **不要在自我介绍里平铺六个项目** —— 重锤 **LoveSpouse + AI 漏洞研判**，其余一句话带过。
