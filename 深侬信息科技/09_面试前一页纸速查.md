## 四、★ 架构题五步法（任何设计题都走这个）

1. **问约束** —— 规模？一致性？可用性？延迟？**团队多少人**？
   - **"我可以先说我的假设，如果不对你再纠正我"** ← 这句保命
2. **定边界** —— 做什么，**不做什么**（"轮子能买就不造"）
3. **分层** —— 先画数据流，再切模块，每层一句话说职责
4. **选型给理由** —— "候选有 A/B，约束是 Z，**我选 A，代价是放弃了 B 的 Y**"
5. **⭐ 说风险和兜底** —— **"我会先做一个 POC 验证最关键的假设"**

> ⭐ **最核心的一条**：**主动说出方案的代价** —— 这是架构师和普通开发的分水岭。

## 五、必须记住的技术要点

### 网关（05 篇精华）

- **Go 的 `httputil.ReverseProxy`：`FlushInterval = -1`** ← 流式必须，否则用户看到"卡住半天然后一次全出来"
- ⚠️ **`http.Transport` 默认 `MaxIdleConnsPerHost = 2`** —— 高并发下疯狂建连、TIME_WAIT 暴涨
- **限流算法**：固定窗口（临界问题）→ 滑动窗口 → 漏桶 → **令牌桶（burst 参数是应对突发的关键）**
- **熔断三态**：Closed → Open → Half-Open；**Google SRE 自适应熔断**（成功率 + 请求量双条件）
- **负载均衡**：一致性哈希（虚拟节点解决数据倾斜）、P2C
- **TLS 三种模式**：卸载 / 透传 / 双向 mTLS

### AI 安全（06 篇精华）

- **AI 流量三特征**：**流式（禁缓冲）、长连接（按连接数算容量）、Token 计量（不能按 QPS 限流）**
- **Prompt 注入的本质**：**LLM 没有"指令"和"数据"的天然隔离** —— 没有根治方案
- **注入防护的核心思想**：**不指望模型不被骗，保证被骗了也没权限造成不可逆后果**（最小权限 + 人工兜底）
- **流式审核**：已发出的收不回来 → **缓冲窗口 / 快速中断 / 按风险分级**
- **OWASP LLM Top 10 里跟网关相关的四类**：提示注入、敏感信息泄露、过度代理、模型拒绝服务
- **Token 计费**：**预扣 → 结算 → 异常兜底**（宁可多扣，不能让人靠中断逃费）

### Go 底层（04 篇精华）

- **GMP**：G 是 goroutine，M 是内核线程，P 是调度上下文（本地队列）。**P 的数量 = GOMAXPROCS**
- **work stealing**：P 本地队列空了，先偷全局队列，再偷其他 P 的
- **GC 三色标记 + 混合写屏障**；真正影响延迟的是 **mark assist**
- **逃逸分析**：`go build -gcflags="-m"` 看逃逸
- **为什么 Go 能做高并发连接**：**netpoller** —— 网络 IO 就绪才唤醒 goroutine，阻塞不占线程

### 集群（07 篇精华）

- **控制平面 vs 数据平面**：控制平面挂了只影响"下发新配置"，**不影响现有流量**
- **ETCD 三件宝**：**Watch**（配置热更新的基础）、**Lease**（节点心跳/故障检测）、**Raft**（CP，宁可不可用也不会两个版本）
- **故障判断要做两级**：租约过期只是"疑似"，先停止导流不杀进程；连续 N 次失败才判定真故障
- **配置原子生效**：预下发 → 全部回报就绪 → 统一下达生效（简化的两阶段提交）+ 分批灰度
- **K8s 迁移话术**：**"Compose 是我手写服务定义、手动扩副本；K8s 是声明式的——我描述期望状态，它负责收敛"**

## 六、八条救场模板（不会的时候照着说）

| 场景 | 话术 |

| **完全没听过** | "这个概念我没接触过，**能麻烦您说下背景吗**？我想确认是不是同一个东西。" → 听完后："按您说的，我的理解是……**如果是我做，我可能会从 XX 切入**" |

| **面试官说错了** | "这个点我想确认一下——**我理解的是……，是不是我哪里理解偏了？**" （**不要争**） |
