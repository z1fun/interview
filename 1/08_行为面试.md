# 08｜行为面试与协作

## STAR 模板

**S**：背景和限制；**T**：你承担的目标；**A**：你亲自做出的判断与行动；**R**：可验证结果和复盘。每题控制在 1–2 分钟，重点使用“我”而非泛泛的“我们”。

## 题目：快速学习并落地新技术

可用 AI 漏洞研判的 LangGraph/RAG，或数字人的 Gemini Live 做素材。回答顺序：面对的新业务目标 → 快速梳理官方能力与最小验证 → 用一个小链路验证风险 → 设定接口与监控 → 与产品/测试联调上线 → 得到的结果和下一步要补的评测/容灾。务必替换为真实经历。

## 题目：处理线上问题

选一个真实的消息重复、链路延迟、外部服务异常或数据问题。说清楚：告警/用户反馈如何发现；先如何止血；用哪些日志、指标、trace 定位；修复的技术机制；怎样通过测试、监控、runbook 防止复发。没有真实线上事故可说压测或预发问题，但必须如实说明场景。

## 题目：跨团队推进

在数字人或 POS 项目中，描述产品定义不清、客户端协议变动或外部 API 限制的案例。重点不是“协调很多人”，而是如何把模糊问题变成协议、边界、验收项和负责人，并通过短周期同步减少返工。

## 离职与动机

保持正向：希望从已有的 AI Agent、实时会话落地经验出发，进入更贴近真实用户交互的产品场景，承担完整服务链路与稳定性责任。避免贬低前东家或只谈薪资。
