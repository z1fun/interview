# 04｜LLM / Agent 工程化

## 推荐架构

会话编排服务负责状态与业务流程；模型网关统一供应商适配、流式、重试、成本记录；工具层提供受控业务能力；记忆/RAG 层提供上下文；异步任务处理摘要、评测和长耗时工作。早期可以是模块化单体，接口和状态边界先清楚，再按瓶颈拆分。

## 模型调用的可靠性

请求必须有 timeout、trace ID、模型版本、Prompt 版本和用户/会话标识。将错误分成参数/安全错误（不重试）、网络/5xx（有限重试）、限流（退避或排队）。为核心场景设置备用模型或降级回复；不要因一次模型失败导致计费或会话状态不一致。

## Tool Calling

工具 schema 只是第一层。服务端仍需校验参数、用户权限、资源归属与额度；具有副作用的工具必须有幂等键、审计记录和必要确认。模型输出永远不应被直接当作 SQL、Shell 命令或内部权限凭据。

## 记忆与 RAG

记忆关注“用户关系连续性”，RAG 关注“外部事实依据”。两者都应记录来源、时间和置信度。召回流程可为：查询改写 → 向量/关键词检索 → 重排 → 取少量片段 → 引用/约束生成。评测至少覆盖召回相关性、答案正确性、拒答正确性、延迟和成本。

## 评估和可观测性

线上记录首 Token、总耗时、输入输出 Token、工具成功率、重试、拒答率和用户反馈；离线维护有标准答案或评分规则的评测集。Prompt、模型和工具 schema 都要版本化，变更先回归再灰度。观察到坏结果时，沿 trace 回看输入、召回、工具和模型输出，不能只凭主观改 Prompt。

## 安全

防御 Prompt 注入的关键是最小权限：不可信文本与系统指令隔离；工具白名单；敏感数据按需脱敏；输出过审核；高风险动作需用户确认或人工介入。陪聊场景还需针对未成年人、诱导付费、隐私和违规内容制定更严格的策略。
