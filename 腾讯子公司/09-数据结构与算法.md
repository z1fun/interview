## 一、常用数据结构的 Go 实现与复杂度

### 1.1 数组与切片

**Go 切片的本质**：一个 24 字节的结构体（64 位下），包含 `array 指针 + len + cap`。

```go
type slice struct {
    array unsafe.Pointer // 底层数组指针
    len   int            // 当前长度
    cap   int            // 容量（决定何时扩容）
}
```

**面试高频点（比算法本身还常问）**：

```go
s := make([]int, 3, 5)   // len=3 cap=5，值是 [0 0 0]
s = append(s, 1)         // len=4 cap=5，没触发扩容
s = append(s, 1, 1)      // len=6 > cap=5 → 扩容，底层数组换新，返回新切片

// 坑 1：append 可能返回新底层数组，旧切片的修改不再可见
a := []int{1, 2, 3}
b := append(a, 4)   // cap 不够，b 指向新数组
b[0] = 100
fmt.Println(a)      // [1 2 3]，a 没变

// 坑 2：切片共享底层数组（"内存泄漏"经典来源）
func bad() []int {
    big := make([]int, 1<<20)   // 8MB
    return big[:2]              // 小切片持有整个大数组的引用，8MB 无法释放
}
// 修法：copy 出来
func good() []int {
    big := make([]int, 1<<20)
    out := make([]int, 2)
    copy(out, big[:2])
    return out
}

// 坑 3：range 拷贝的是元素副本（值类型时改了没用）
type User struct{ Name string }
users := []User{{"a"}, {"b"}}
for _, u := range users {
    u.Name = "x"        // ❌ 改的是副本，users 不变
}
for i := range users {
    users[i].Name = "x" // ✅ 按下标改
}
```

**扩容规则**（Go 1.18+ 大致）：小于 256 元素时翻倍扩容；大于 256 时按 1.25 倍增长（`newcap += (newcap + 3*256) / 4`），并做内存对齐。面试只需说「小切片翻倍、大切片约 1.25 倍，避免大内存浪费」。

**复杂度速查**：

| 操作 | 复杂度 | 说明 |
|---|---|---|
| 按下标访问 | O(1) | 连续内存 |
| 尾部 append | 均摊 O(1) | 偶尔扩容 O(n) |
| 中间插入/删除 | O(n) | 需要搬移后续元素 |
| 查找（无序） | O(n) | 线性扫描 |
| 查找（有序） | O(log n) | 二分 |

**工程技巧**：预分配容量 `make([]int, 0, n)` 避免多次扩容；`s = s[:0]` 复用切片（不释放内存但零分配）。

### 1.2 链表

```go
type ListNode struct {
    Val  int
    Next *ListNode
}
```

#### 反转链表（迭代 + 递归，必背）

```go
// 迭代：三指针，画图理解 pre/cur/next
func reverseList(head *ListNode) *ListNode {
    var pre *ListNode          // 前驱，初始为 nil（反转后的尾节点）
    cur := head
    for cur != nil {
        nxt := cur.Next        // ① 先存下一个，否则断链后找不到
        cur.Next = pre         // ② 反转指针方向
        pre = cur              // ③ 前驱后移
        cur = nxt              // ④ 当前后移
    }
    return pre                 // pre 停在原链表最后一个节点 = 新头
}

// 递归：假设后面的已经反转好，处理当前节点
func reverseListRec(head *ListNode) *ListNode {
    if head == nil || head.Next == nil {
        return head            // 终止条件：空节点或只剩一个
    }
    newHead := reverseListRec(head.Next)  // 后面的全部反转完，newHead 是新头
    head.Next.Next = head      // 让后继指回自己
    head.Next = nil            // 断开自己原来的指向，否则成环
    return newHead
}
```

#### 环检测（快慢指针 / Floyd 判圈）

```go
// 判断有环：快指针每次 2 步，慢指针 1 步；有环必然相遇
func hasCycle(head *ListNode) bool {
    slow, fast := head, head
    for fast != nil && fast.Next != nil {
        slow = slow.Next
        fast = fast.Next.Next
        if slow == fast {
            return true
        }
    }
    return false
}

// 找入环点（LeetCode 142）：相遇后，一个指针回头部，两指针同速前进，再次相遇处即入环点
func detectCycle(head *ListNode) *ListNode {
    slow, fast := head, head
    for fast != nil && fast.Next != nil {
        slow = slow.Next
        fast = fast.Next.Next
        if slow == fast {           // 相遇点
            p := head
            for p != slow {         // 同速前进
                p = p.Next
                slow = slow.Next
            }
            return p                // 入环点
        }
    }
    return nil
}
```

**为什么「回头部同速走一定在入环点相遇」？**（面试官爱追问，要能推导）
设头到入环点距离 `a`，入环点到相遇点距离 `b`，环长 `L`（相遇点到入环点为 `c`，`b + c = L`）。
相遇时慢指针走了 `a + b`，快指针走了 `a + b + kL`，且快指针路程是慢指针 2 倍：
`2(a + b) = a + b + kL` → `a + b = kL` → `a = kL - b = (k-1)L + c`。
即「从头走 a 步」等于「从相遇点走 c 步再加若干整圈」，所以两指针必然在入环点相遇。

**复杂度**：时间 O(n)，空间 O(1)（对比哈希表存访问过的节点是 O(n) 空间——面试时说出这个对比就是加分）。

#### 其他必会链表操作

```go
// 合并两个有序链表（LeetCode 21）：哑结点技巧，避免处理头节点的特判
func mergeTwoLists(l1, l2 *ListNode) *ListNode {
    dummy := &ListNode{}
    cur := dummy
    for l1 != nil && l2 != nil {
        if l1.Val <= l2.Val {
            cur.Next, l1 = l1, l1.Next
        } else {
            cur.Next, l2 = l2, l2.Next
        }
        cur = cur.Next
    }
    if l1 != nil { cur.Next = l1 } else { cur.Next = l2 }
    return dummy.Next
}

// 删除倒数第 N 个节点（LeetCode 19）：快指针先走 N 步，再同速，慢指针停在待删节点前驱
func removeNthFromEnd(head *ListNode, n int) *ListNode {
    dummy := &ListNode{Next: head}   // 哑结点：处理「删除头节点」的情况
    slow, fast := dummy, dummy
    for i := 0; i < n; i++ { fast = fast.Next }
    for fast.Next != nil {
        slow = slow.Next
        fast = fast.Next
    }
    slow.Next = slow.Next.Next
    return dummy.Next
}

// 找中点（快慢指针）：常用于链表归并排序的切分
func middleNode(head *ListNode) *ListNode {
    slow, fast := head, head
    for fast != nil && fast.Next != nil {
        slow = slow.Next
        fast = fast.Next.Next
    }
    return slow
}
```

> **面试技巧**：链表题一律先写 `dummy := &ListNode{Next: head}`（哑结点），可以省掉「操作头节点」的特判，减少出错。写完后主动说出边界：空链表、只有一个节点、删除头/尾节点。

#### 单调栈：解决「下一个更大/更小元素」类问题

**适用场景**：求每个元素左边/右边第一个比它大（小）的元素。典型题：每日温度（739）、下一个更大元素（496）、接雨水（42）、柱状图中最大矩形（84）。

```go
// LeetCode 739 每日温度：返回「还要等几天才会升温」
// 单调递减栈（存下标，栈内温度递减）；遇到比栈顶高的，就结算栈顶
func dailyTemperatures(temperatures []int) []int {
    n := len(temperatures)
    ans := make([]int, n)
    stack := make([]int, 0, n)      // 存下标
    for i := 0; i < n; i++ {
        // 当前温度 > 栈顶对应温度 → 栈顶的「下一个更高温」就是今天
        for len(stack) > 0 && temperatures[i] > temperatures[stack[len(stack)-1]] {
            top := stack[len(stack)-1]
            stack = stack[:len(stack)-1]
            ans[top] = i - top
        }
        stack = append(stack, i)
    }
    return ans                   // 栈里剩下的说明后面没有更高温，保持 0
}
```

**单调栈的思维模型**（口述时用）：
- 单调栈维护的是一个「**还没找到答案的候选集合**」，并且这个集合的元素是单调的。
- 新元素进来时，把所有「被它淘汰」的栈顶元素弹出并结算答案。
- **每个元素最多进栈一次、出栈一次**，所以是 O(n)，比暴力 O(n²) 快。
- 栈里存**下标**而不是值：因为答案往往需要算距离/宽度。

#### 单调队列：滑动窗口最大值（LeetCode 239）

```go
// 单调递减队列（存下标），队首永远是窗口内最大值的下标
func maxSlidingWindow(nums []int, k int) []int {
    ans := make([]int, 0, len(nums)-k+1)
    q := make([]int, 0, k)          // 双端队列（用切片模拟）
    for i, v := range nums {
        // ① 队尾淘汰：比新元素小的都不可能再成为最大值
        for len(q) > 0 && nums[q[len(q)-1]] <= v {
            q = q[:len(q)-1]
        }
        q = append(q, i)
        // ② 队首淘汰：下标已经滑出窗口
        if q[0] <= i-k {
            q = q[1:]
        }
        // ③ 窗口形成后开始记录答案
        if i >= k-1 {
            ans = append(ans, nums[q[0]])
        }
    }
    return ans
}
```

**面试要点**：为什么是 O(n)？因为每个元素最多入队一次、出队一次。对比「每 k 个元素扫一遍」的 O(nk) 和「大顶堆」的 O(n log k)。

### 1.4 二叉树

```go
type TreeNode struct {
    Val   int
    Left  *TreeNode
    Right *TreeNode
}
```

#### 四种遍历（递归版 + 迭代版，全都要会）

```go
// ---------- 前序（根左右）----------
func preorderRec(root *TreeNode) []int {
    var ans []int
    var dfs func(*TreeNode)
    dfs = func(n *TreeNode) {
        if n == nil { return }
        ans = append(ans, n.Val)
        dfs(n.Left)
        dfs(n.Right)
    }
    dfs(root)
    return ans
}

// 迭代版：用栈，注意「先压右再压左」才能保证左先出栈
func preorderIter(root *TreeNode) []int {
    if root == nil { return nil }
    var ans []int
    stack := []*TreeNode{root}
    for len(stack) > 0 {
        n := stack[len(stack)-1]
        stack = stack[:len(stack)-1]
        ans = append(ans, n.Val)
        if n.Right != nil { stack = append(stack, n.Right) }
        if n.Left != nil  { stack = append(stack, n.Left) }
    }
    return ans
}

// ---------- 中序（左根右）：BST 中序是升序序列 ----------
func inorderIter(root *TreeNode) []int {
    var ans []int
    var stack []*TreeNode
    cur := root
    for cur != nil || len(stack) > 0 {
        for cur != nil {              // 一路向左，把路径压栈
            stack = append(stack, cur)
            cur = cur.Left
        }
        cur = stack[len(stack)-1]     // 弹出栈顶 = 最左未访问节点
        stack = stack[:len(stack)-1]
        ans = append(ans, cur.Val)
        cur = cur.Right               // 转向右子树
    }
    return ans
}

// ---------- 后序（左右根）：把「根右左」的结果反转 ----------
func postorderIter(root *TreeNode) []int {
    if root == nil { return nil }
    var ans []int
    stack := []*TreeNode{root}
    for len(stack) > 0 {
        n := stack[len(stack)-1]
        stack = stack[:len(stack)-1]
        ans = append(ans, n.Val)
        if n.Left != nil  { stack = append(stack, n.Left) }   // 注意：先左后右
        if n.Right != nil { stack = append(stack, n.Right) }
    }
    // 此时是「根右左」，反转即「左右根」
    for i, j := 0, len(ans)-1; i < j; i, j = i+1, j-1 {
        ans[i], ans[j] = ans[j], ans[i]
    }
    return ans
}

// ---------- 层序（BFS）：按层分组，很多题的骨架 ----------
func levelOrder(root *TreeNode) [][]int {
    if root == nil { return nil }
    var ans [][]int
    queue := []*TreeNode{root}
    for len(queue) > 0 {
        size := len(queue)          // 关键：先记录当前层节点数
        level := make([]int, 0, size)
        for i := 0; i < size; i++ {
            n := queue[0]
            queue = queue[1:]
            level = append(level, n.Val)
            if n.Left != nil  { queue = append(queue, n.Left) }
            if n.Right != nil { queue = append(queue, n.Right) }
        }
        ans = append(ans, level)
    }
    return ans
}
```

**复杂度**：时间 O(n)（每节点访问一次），空间 O(h)（递归栈深度，最坏退化成链表为 O(n)）或 O(w)（BFS 队列，w 为最大宽度）。

**面试常问**：「递归和迭代怎么选？」
> 「递归写法短、可读性好，但深度受栈限制，链式二叉树可能栈溢出；迭代用显式栈，空间一样是 O(h)，但不会爆栈。工程上如果树的深度不可控（比如用树结构存组织架构，可能很深），我会用迭代或加深度限制。」

#### 二叉树高频变形

```go
// 最大深度（LeetCode 104）
func maxDepth(root *TreeNode) int {
    if root == nil { return 0 }
    return 1 + max(maxDepth(root.Left), maxDepth(root.Right))
}

// 最近公共祖先（LeetCode 236）：后序遍历，左右各自找
func lowestCommonAncestor(root, p, q *TreeNode) *TreeNode {
    if root == nil || root == p || root == q { return root }
    left := lowestCommonAncestor(root.Left, p, q)
    right := lowestCommonAncestor(root.Right, p, q)
    if left != nil && right != nil { return root }   // p、q 分别在两侧 → 当前节点就是 LCA
    if left != nil { return left }                   // 都在左侧
    return right
}

// 验证二叉搜索树（LeetCode 98）：中序遍历必须严格递增
func isValidBST(root *TreeNode) bool {
    var prev *TreeNode
    var stack []*TreeNode
    cur := root
    for cur != nil || len(stack) > 0 {
        for cur != nil { stack = append(stack, cur); cur = cur.Left }
        cur = stack[len(stack)-1]; stack = stack[:len(stack)-1]
        if prev != nil && prev.Val >= cur.Val { return false }  // 严格递增
        prev, cur = cur, cur.Right
    }
    return true
}
```

**`isValidBST` 的经典坑**：不能只比较「左孩子 < 根 < 右孩子」，因为 BST 要求**整棵左子树**都小于根。两种正确做法：① 中序遍历判断递增；② 递归带上下界 `(min, max)`。

### 1.5 二叉搜索树（BST）

**性质**：左子树全部 < 根 < 右子树全部；**中序遍历得到升序序列**（这条性质是所有 BST 题的钥匙）。

| 操作 | 平均 | 最坏（退化成链表） |
|---|---|---|
| 查找 | O(log n) | O(n) |
| 插入 | O(log n) | O(n) |
| 删除 | O(log n) | O(n) |

**为什么工程上更常用平衡树/跳表**：BST 的退化是真实风险（有序插入即可退化成链表）。MySQL 用 B+ 树、Redis ZSet 用跳表、Go map 用哈希——**都是为了稳定地把最坏情况压到 O(log n) 或 O(1)**。面试问到「为什么数据库不用 BST」时，这就是标准答案的一部分。

```go
// BST 查找 + 插入
func searchBST(root *TreeNode, val int) *TreeNode {
    for root != nil {
        switch {
        case val == root.Val: return root
        case val < root.Val:  root = root.Left
        default:              root = root.Right
        }
    }
    return nil
}
```

### 1.6 堆（优先队列）

**堆的性质**：完全二叉树，用**数组**存储（下标 i 的左右孩子是 `2i+1`、`2i+2`，父节点是 `(i-1)/2`）。大顶堆：每个父节点 ≥ 孩子。

```go
// 手写小顶堆（面试手写版，比 container/heap 更能展示理解）
type MinHeap struct {
    data []int
}

func (h *MinHeap) Len() int { return len(h.data) }

func (h *MinHeap) Push(v int) {
    h.data = append(h.data, v)
    h.up(len(h.data) - 1)          // 上浮
}

func (h *MinHeap) Pop() (int, bool) {
    if len(h.data) == 0 { return 0, false }
    top := h.data[0]
    last := len(h.data) - 1
    h.data[0] = h.data[last]       // 末尾元素补到堆顶
    h.data = h.data[:last]
    h.down(0)                      // 下沉
    return top, true
}

func (h *MinHeap) up(i int) {
    for i > 0 {
        parent := (i - 1) / 2
        if h.data[parent] <= h.data[i] { break }
        h.data[parent], h.data[i] = h.data[i], h.data[parent]
        i = parent
    }
}

func (h *MinHeap) down(i int) {
    n := len(h.data)
    for {
        l, r, min := 2*i+1, 2*i+2, i
        if l < n && h.data[l] < h.data[min] { min = l }
        if r < n && h.data[r] < h.data[min] { min = r }
        if min == i { break }
        h.data[i], h.data[min] = h.data[min], h.data[i]
        i = min
    }
}
```

**标准库写法（面试可用，要说明）**：

```go
import "container/heap"

type IntHeap []int
func (h IntHeap) Len() int           { return len(h) }
func (h IntHeap) Less(i, j int) bool { return h[i] < h[j] }  // 小顶堆；改成 > 就是大顶堆
func (h IntHeap) Swap(i, j int)      { h[i], h[j] = h[j], h[i] }
func (h *IntHeap) Push(x any)        { *h = append(*h, x.(int)) }
func (h *IntHeap) Pop() any {
    old := *h
    n := len(old)
    x := old[n-1]
    *h = old[:n-1]
    return x
}
// 使用：h := &IntHeap{}; heap.Init(h); heap.Push(h, 3); v := heap.Pop(h).(int)
```

#### TopK 问题（面试超高频，客服系统场景也很真实）

**问题**：从 N 个元素中找最大的 K 个（比如「统计最近一小时调用量 Top10 的接口」）。

| 方案 | 复杂度 | 适用 |
|---|---|---|
| 全排序取前 K | O(n log n) | K 接近 n 时 |
| **小顶堆（大小 K）** | O(n log k) | **K 远小于 n 时最优**，且适合**数据流**场景 |
| 快速选择（quickselect） | 平均 O(n) | 数据一次性给全、内存放得下，会改变原数组 |
| 分治 + 归并 | O(n log k) | 海量数据（MapReduce 思路） |

```go
// 用 K 大小的小顶堆求最大 K 个：堆顶是这 K 个里最小的，比它小就直接丢
func topK(nums []int, k int) []int {
    if k <= 0 || k > len(nums) { return nil }
    h := &MinHeap{}
    for _, v := range nums {
        if h.Len() < k {
            h.Push(v)
        } else if v > h.data[0] {      // 比堆顶大才有资格进入 TopK
            h.Pop()
            h.Push(v)
        }
    }
    return h.data
}

// LeetCode 215 数组中的第 K 个最大元素：快速选择（平均 O(n)）
func findKthLargest(nums []int, k int) int {
    target := len(nums) - k           // 第 k 大 = 升序后的第 len-k 个下标
    lo, hi := 0, len(nums)-1
    for lo <= hi {
        p := partition(nums, lo, hi)  // 分区，返回基准最终位置
        switch {
        case p == target: return nums[p]
        case p < target:  lo = p + 1
        default:          hi = p - 1
        }
    }
    return -1
}

func partition(a []int, lo, hi int) int {
    pivot := a[hi]                    // 取最后一个为基准（随机化可避免最坏情况）
    i := lo
    for j := lo; j < hi; j++ {
        if a[j] < pivot {
            a[i], a[j] = a[j], a[i]
            i++
        }
    }
    a[i], a[hi] = a[hi], a[i]
    return i
}
```

> **话术提示（把算法题接到业务上，面试官很吃这套）**：
> 「TopK 我在数据中台项目里真用过类似的思路——需要统计各门店销量排行，数据量大的时候不是全量排序，而是维护一个大小为 K 的小顶堆。
> 如果是分布式场景（多台收银机各自上报），就是每台机器先算本地 TopK，再汇总算全局 TopK，也就是 MapReduce 的 combine 思路。」

### 1.7 哈希表

**Go map 的底层（面试常问「Go 的 map 为什么快」）**：

- **hmap + bmap（桶）**：每个桶存 8 个 key-value，用**开放寻址中的拉链法变体**——桶内是数组，桶满后溢出桶用链表串起来。
- **渐进式扩容**：装载因子超过 6.5 或溢出桶过多时触发扩容，扩容时**不是一次性 rehash**，而是每次操作搬一两个桶（`oldbuckets`），避免大 map 扩容时的卡顿（这一点和 Redis 的渐进式 rehash 思路一致，可以横向对比）。
- **无序**：遍历顺序随机（故意设计，防止开发者依赖顺序）。
- **不可寻址**：`m[key].Field = 1` 编译报错，因为扩容后地址会变。要先取出来改再放回去。
- **并发不安全**：并发读写会直接 panic（`fatal error: concurrent map writes`），需要用 `sync.RWMutex` 或 `sync.Map`。

```go
// 哈希表三大用法：计数、去重、查找配对
// ① 计数
count := make(map[string]int)
for _, ip := range ips { count[ip]++ }

// ② 查找配对（LeetCode 1 两数之和）：空间换时间，O(n) → O(1) 查找
func twoSum(nums []int, target int) []int {
    seen := make(map[int]int, len(nums))   // 值 → 下标
    for i, v := range nums {
        if j, ok := seen[target-v]; ok {
            return []int{j, i}
        }
        seen[v] = i
    }
    return nil
}

// ③ 前缀和 + 哈希（LeetCode 560 和为 K 的子数组）：把「子数组和」转成「两个前缀和之差」
func subarraySum(nums []int, k int) int {
    cnt := map[int]int{0: 1}      // 前缀和为 0 出现 1 次（空前缀）
    sum, ans := 0, 0
    for _, v := range nums {
        sum += v
        ans += cnt[sum-k]         // 之前有多少个前缀和等于 sum-k，就有多少个子数组和为 k
        cnt[sum]++
    }
    return ans
}
```

**哈希表 vs 其他结构的选择（面试官爱问判断力）**：

| 需求 | 选择 |
|---|---|
| 快速查找/去重/计数 | 哈希表 O(1) |
| 需要有序遍历 / 范围查询 | 平衡树、跳表 O(log n) |
| 内存敏感、数据量极大 | 布隆过滤器（有误判，可能把不存在的说成存在） |
| 需要并发写 | `sync.Map`（读多写少）或分片锁 map |

#### DFS 与 BFS（LeetCode 200 岛屿数量，图遍历的模板题）

```go
// DFS 版本：染色标记，把访问过的陆地沉掉
func numIslands(grid [][]byte) int {
    if len(grid) == 0 { return 0 }
    m, n := len(grid), len(grid[0])
    var dfs func(i, j int)
    dfs = func(i, j int) {
        if i < 0 || i >= m || j < 0 || j >= n || grid[i][j] != '1' { return }
        grid[i][j] = '0'                    // 标记已访问（避免额外 visited 数组）
        dfs(i+1, j); dfs(i-1, j)
        dfs(i, j+1); dfs(i, j-1)
    }
    cnt := 0
    for i := 0; i < m; i++ {
        for j := 0; j < n; j++ {
            if grid[i][j] == '1' {
                cnt++
                dfs(i, j)
            }
        }
    }
    return cnt
}

// BFS 版本（多源 BFS 也可用于 LeetCode 994 腐烂的橘子）
func numIslandsBFS(grid [][]byte) int {
    if len(grid) == 0 { return 0 }
    m, n := len(grid), len(grid[0])
    dirs := [4][2]int{{1, 0}, {-1, 0}, {0, 1}, {0, -1}}
    cnt := 0
    for i := 0; i < m; i++ {
        for j := 0; j < n; j++ {
            if grid[i][j] != '1' { continue }
            cnt++
            queue := [][2]int{{i, j}}
            grid[i][j] = '0'
            for len(queue) > 0 {
                cur := queue[0]; queue = queue[1:]
                for _, d := range dirs {
                    ni, nj := cur[0]+d[0], cur[1]+d[1]
                    if ni >= 0 && ni < m && nj >= 0 && nj < n && grid[ni][nj] == '1' {
                        grid[ni][nj] = '0'
                        queue = append(queue, [2]int{ni, nj})
                    }
                }
            }
        }
    }
    return cnt
}
```

**DFS vs BFS 选择**：

| | DFS | BFS |
|---|---|---|
| 实现 | 递归/栈 | 队列 |
| 适合 | 连通性、路径存在性、回溯类、拓扑排序 | **最短路径（无权图）**、层序、多源扩散 |
| 空间 | O(h) 递归栈 | O(w) 最宽一层 |
| 缺点 | 深度大可能爆栈 | 队列可能占用较大内存 |

**关键结论**：**无权图的最短路径必须用 BFS**（因为 BFS 按层扩散，第一次到达即最短）；DFS 找到的路径不保证最短。

#### 拓扑排序（OA 审批流依赖的真实场景）

**场景**：一个审批流程里，A 节点必须在 B 之前完成；或者编译时的依赖关系；或者课程安排。这类「有向无环图（DAG）的线性排序」就是拓扑排序。

```go
// LeetCode 207 课程表：判断能否完成所有课程（即是否存在环）
// Kahn 算法（BFS）：统计入度，入度为 0 的入队，逐个「摘除」并更新邻居入度
func canFinish(numCourses int, prerequisites [][]int) bool {
    g := make([][]int, numCourses)
    indeg := make([]int, numCourses)
    for _, p := range prerequisites {       // p = [course, pre]
        g[p[1]] = append(g[p[1]], p[0])
        indeg[p[0]]++
    }
    queue := make([]int, 0, numCourses)
    for i, d := range indeg {
        if d == 0 { queue = append(queue, i) }   // 入度为 0 = 无前置依赖，可以开始
    }
    done := 0
    for len(queue) > 0 {
        cur := queue[0]; queue = queue[1:]
        done++
        for _, next := range g[cur] {
            indeg[next]--
            if indeg[next] == 0 { queue = append(queue, next) }
        }
    }
    return done == numCourses      // 能摘除全部节点 = 无环
}

// LeetCode 210 课程表 II：返回拓扑序（把出队顺序记下来即可）
```

**三种做法对比（口述加分点）**：
1. **Kahn（BFS 入度法）**：直观，能检测环（结果数量 < 节点数即有环），能顺便输出拓扑序。
2. **DFS + 三色标记**：白色未访问、灰色在栈中（遇到灰色说明有环）、黑色已完成；后序逆序即拓扑序。
3. **工程应用**：工作流引擎（OA 审批流）、任务调度 DAG（Airflow/Argo）、依赖注入容器初始化顺序。

#### 最短路径

| 算法 | 适用 | 复杂度 | 能否处理负权 |
|---|---|---|---|
| BFS | 无权图 | O(V+E) | — |
| Dijkstra（堆优化） | 非负权，单源 | O((V+E) log V) | ❌ |
| Bellman-Ford | 可负权，能检测负环 | O(VE) | ✅ |
| Floyd | 多源，小图 | O(V³) | ✅（无负环） |

```go
import "container/heap"

type edge struct{ to, w int }
type item struct {
    node, dist int
}
type pq []item
func (p pq) Len() int            { return len(p) }
func (p pq) Less(i, j int) bool  { return p[i].dist < p[j].dist }
func (p pq) Swap(i, j int)       { p[i], p[j] = p[j], p[i] }
func (p *pq) Push(x any)         { *p = append(*p, x.(item)) }
func (p *pq) Pop() any           { old := *p; n := len(old); x := old[n-1]; *p = old[:n-1]; return x }

// Dijkstra（堆优化）：单源最短路径，边权非负
func dijkstra(n int, g [][]edge, start int) []int {
    const INF = 1 << 30
    dist := make([]int, n)
    for i := range dist { dist[i] = INF }
    dist[start] = 0

    h := &pq{{start, 0}}
    for h.Len() > 0 {
        cur := heap.Pop(h).(item)
        if cur.dist > dist[cur.node] { continue }   // 过期条目，跳过（懒删除）
        for _, e := range g[cur.node] {
            nd := cur.dist + e.w
            if nd < dist[e.to] {                     // 松弛
                dist[e.to] = nd
                heap.Push(h, item{e.to, nd})
            }
        }
    }
    return dist
}
```

**面试要点**：Dijkstra 不能有负权边（贪心地认为「已确定的最短距离不会再被更新」，负权会打破这个前提）；需要负权用 Bellman-Ford。

## 二、排序与搜索

### 2.1 快速排序

**核心思想（分治）**：选一个基准（pivot），把数组分成「小于基准」和「大于基准」两部分，然后递归处理两边。

- **平均 O(n log n)，最坏 O(n²)**（每次选的基准都是当前最大/最小值，退化成冒泡），**空间 O(log n)**（递归栈），**不稳定**。
- **最坏情况怎么避免**：随机选基准 / 三数取中（取首、中、尾的中位数）。
- **工程优化**：小区间（如 length < 12）改用插入排序（减少递归开销）；三路分区处理大量重复元素。

```go
// 快速排序（随机化基准，避免有序数组退化）
func quickSort(nums []int) {
    var sort func(lo, hi int)
    sort = func(lo, hi int) {
        if lo >= hi { return }
        p := partitionRandom(nums, lo, hi)
        sort(lo, p-1)
        sort(p+1, hi)
    }
    sort(0, len(nums)-1)
}

func partitionRandom(a []int, lo, hi int) int {
    // 随机选基准并换到末尾，避免对已排序数组退化成 O(n²)
    idx := lo + rand.Intn(hi-lo+1)
    a[idx], a[hi] = a[hi], a[idx]
    return partition(a, lo, hi)
}
```

**三路快排（荷兰国旗问题）**——当数组有大量重复元素时，普通快排会退化（等于基准的元素都挤在一边，递归不平衡）：

```go
// 三路分区：把数组分成 < pivot | == pivot | > pivot 三段
// 返回等于区的左右边界
func quickSort3Way(a []int, lo, hi int) {
    if lo >= hi { return }
    pivot := a[lo+rand.Intn(hi-lo+1)]

    lt, i, gt := lo, lo, hi     // [lo, lt) < p ；[lt, i) == p ；(gt, hi] > p
    for i <= gt {
        switch {
        case a[i] < pivot:
            a[lt], a[i] = a[i], a[lt]
            lt++
            i++
        case a[i] > pivot:
            a[gt], a[i] = a[i], a[gt]
            gt--                 // 注意：i 不前进，换过来的元素还没检查
        default:
            i++                  // 等于基准，直接跳过（不进任何递归分支）
        }
    }
    quickSort3Way(a, lo, lt-1)
    quickSort3Way(a, gt+1, hi)
}
```

**复杂度直观理解**：每次分区花 O(n)，理想情况下分 log n 层，共 O(n log n)；如果每次只分出 1 个元素，就变成 n 层，O(n²)。

**为什么快排比归并快（实际工程中）**：虽然同为 O(n log n)，但快排是**原地排序**（不需要额外数组），且顺序访问内存对 CPU 缓存友好，常数因子更小。所以 Go 标准库 `sort.Slice`（pdqsort）用的就是快排的变体 + 插入排序 + 堆排的混合策略。

### 2.2 归并排序

**核心思想**：把数组从中间切分，分别排好序，再合并两个有序数组。

- **稳定 O(n log n)**（最好最坏都一样），**空间 O(n)**（需要辅助数组），**稳定排序**。

```go
func mergeSort(nums []int) []int {
    if len(nums) <= 1 { return nums }
    mid := len(nums) / 2
    left := mergeSort(nums[:mid])
    right := mergeSort(nums[mid:])

    // 合并两个有序数组
    res := make([]int, 0, len(nums))
    i, j := 0, 0
    for i < len(left) && j < len(right) {
        if left[i] <= right[j] {      // <= 保证稳定性
            res = append(res, left[i]); i++
        } else {
            res = append(res, right[j]); j++
        }
    }
    res = append(res, left[i:]...)
    res = append(res, right[j:]...)
    return res
}
```

**归并排序的两个高价值衍生**：

```go
// ① 链表排序（LeetCode 148）：链表归并是链表排序的最优解（快排对链表不友好）
// 思路：快慢指针找中点 → 断开 → 递归排序两半 → 合并（复用 1.2 的 mergeTwoLists）

// ② 统计逆序对（剑指 Offer 51）：合并时右边小于左边，就产生了逆序对
func reversePairs(nums []int) int {
    cnt := 0
    var ms func(a []int) []int
    ms = func(a []int) []int {
        if len(a) <= 1 { return a }
        mid := len(a) / 2
        l, r := ms(a[:mid]), ms(a[mid:])
        res := make([]int, 0, len(a))
        i, j := 0, 0
        for i < len(l) && j < len(r) {
            if l[i] <= r[j] {
                res = append(res, l[i]); i++
            } else {
                cnt += len(l) - i     // 左边剩余所有元素都与 r[j] 构成逆序对
                res = append(res, r[j]); j++
            }
        }
        res = append(res, l[i:]...)
        res = append(res, r[j:]...)
        return res
    }
    ms(nums)
    return cnt
}
```

### 2.3 堆排序

**核心思想**：① 建堆（从最后一个非叶子节点开始下沉，O(n)）；② 反复把堆顶（最大）换到末尾，然后对剩余部分下沉。

```go
func heapSort(a []int) {
    n := len(a)
    // ① 建大顶堆：从最后一个非叶子节点 n/2-1 开始，逐个下沉
    for i := n/2 - 1; i >= 0; i-- {
        siftDown(a, i, n)
    }
    // ② 依次把堆顶换到末尾，堆缩小，重新下沉
    for i := n - 1; i > 0; i-- {
        a[0], a[i] = a[i], a[0]     // 堆顶（最大）归位
        siftDown(a, 0, i)           // 维护剩余部分的堆性质
    }
}

func siftDown(a []int, i, n int) {
    for {
        l, r, maxIdx := 2*i+1, 2*i+2, i
        if l < n && a[l] > a[maxIdx] { maxIdx = l }
        if r < n && a[r] > a[maxIdx] { maxIdx = r }
        if maxIdx == i { return }
        a[i], a[maxIdx] = a[maxIdx], a[i]
        i = maxIdx
    }
}
```

**特点**：**O(n log n) 稳定、原地排序（O(1) 额外空间）、不稳定**。工程价值在于「**只需要前 K 个**」时不用全排序（见 1.6 TopK），以及**实时求中位数**（大小堆各半）。

| 基数排序 | O(d(n+k)) | O(d(n+k)) | O(d(n+k)) | O(n+k) | ✅ | 定长整数/字符串（手机号、IP） |

**面试三连问的标准答案**：
1. 「为什么快排最常用？」→ 原地 + 缓存友好 + 常数小；平均性能最好。
2. 「什么时候用归并？」→ 需要**稳定**、需要**外部排序**（数据大于内存，多路归并）、排**链表**。
3. 「什么时候用堆排？」→ 只要 **TopK**、要求**最坏情况也是 O(n log n)**（如实时系统不能有最坏退化）。
4. 「Go 的 `sort.Slice` 用什么？」→ pdqsort（pattern-defeating quicksort）：快排 + 插入排序（小数组）+ 堆排（检测到退化时切换），保证最坏 O(n log n)。**注意 `sort.Slice` 不稳定，需要稳定排序用 `sort.SliceStable`。**

### 2.5 二分查找及其变体

**二分的前提**：**有序**（或具有单调性/可判定性）。**最容易写错的地方**：边界和循环不变量。

```go
// ① 标准二分：找目标值，返回下标，找不到返回 -1
func binarySearch(nums []int, target int) int {
    lo, hi := 0, len(nums)-1
    for lo <= hi {                     // 闭区间 [lo, hi]，所以 lo == hi 时还要检查
        mid := lo + (hi-lo)/2          // 防溢出写法（Go 里 int 溢出风险小，但这是习惯）
        switch {
        case nums[mid] == target: return mid
        case nums[mid] < target:  lo = mid + 1
        default:                  hi = mid - 1
        }
    }
    return -1
}

// ② 左边界：第一个 >= target 的位置（lower_bound）
// 等价于「target 应该插入的位置」，返回 [0, n]
func lowerBound(nums []int, target int) int {
    lo, hi := 0, len(nums)          // 左闭右开 [lo, hi)
    for lo < hi {
        mid := lo + (hi-lo)/2
        if nums[mid] < target {
            lo = mid + 1            // mid 及之前都不满足，答案在右边
        } else {
            hi = mid                // mid 可能是答案，保留
        }
    }
    return lo                       // lo 是第一个 >= target 的位置
}

// ③ 右边界：最后一个 <= target 的位置，或「第一个 > target 的位置 - 1」
func upperBound(nums []int, target int) int {
    lo, hi := 0, len(nums)
    for lo < hi {
        mid := lo + (hi-lo)/2
        if nums[mid] <= target {
            lo = mid + 1
        } else {
            hi = mid
        }
    }
    return lo                       // 第一个 > target 的位置
}

// ④ LeetCode 34：在排序数组中查找元素的第一个和最后一个位置（左右边界的组合）
func searchRange(nums []int, target int) []int {
    left := lowerBound(nums, target)
    if left == len(nums) || nums[left] != target { return []int{-1, -1} }
    right := upperBound(nums, target) - 1
    return []int{left, right}
}
```

**记忆口诀**：
- **`lo <= hi` + `hi = mid - 1`**：闭区间写法，返回时要判断是否真的找到。
- **`lo < hi` + `hi = mid`**：左闭右开写法，返回 `lo` 就是「第一个满足条件的位置」——**求边界统一用这个模板**。
- 判断条件写 `nums[mid] < target` 就往右收，写 `nums[mid] <= target` 也往右收，区别只在于「等于」时算不算满足条件。

#### 旋转数组（LeetCode 33 / 153，二分的高频变体）

```go
// LeetCode 33 搜索旋转排序数组：总有一半是有序的，判断 target 在不在有序的那一半
func search(nums []int, target int) int {
    lo, hi := 0, len(nums)-1
    for lo <= hi {
        mid := lo + (hi-lo)/2
        if nums[mid] == target { return mid }
        if nums[lo] <= nums[mid] {                 // 左半段有序
            if nums[lo] <= target && target < nums[mid] {
                hi = mid - 1                       // target 在左半段
            } else {
                lo = mid + 1
            }
        } else {                                    // 右半段有序
            if nums[mid] < target && target <= nums[hi] {
                lo = mid + 1
            } else {
                hi = mid - 1
            }
        }
    }
    return -1
}

// LeetCode 153 寻找旋转排序数组中的最小值：和右端点比较
func findMin(nums []int) int {
    lo, hi := 0, len(nums)-1
    for lo < hi {
        mid := lo + (hi-lo)/2
        if nums[mid] < nums[hi] {   // 最小值在左半（含 mid）
            hi = mid
        } else {                     // 最小值在右半
            lo = mid + 1
        }
    }
    return nums[lo]
}
```

#### 二分答案（进阶套路，面试拉开差距的点）

当题目问「**最小的最大值**」「**最大的最小值**」「**最少需要多少天/多少容量**」时，如果**答案具有单调性**（答案 x 可行则 x+1 也可行），就可以**对答案二分**：

```go
// 模板：check(x) 判断答案 x 是否可行；找最小的可行解
func binarySearchAnswer(lo, hi int, check func(int) bool) int {
    for lo < hi {
        mid := lo + (hi-lo)/2
        if check(mid) {
            hi = mid          // mid 可行，试着更小
        } else {
            lo = mid + 1      // mid 不可行，必须更大
        }
    }
    return lo
}
// 典型题：LeetCode 875 爱吃香蕉的珂珂、1011 在 D 天内送达包裹的能力、410 分割数组的最大值
// 业务映射：限流阈值调参、分库分表数量、批量任务每批大小 —— 都是「二分答案」的实际场景
```

## 三、动态规划

### 3.1 解题框架（四步走，口述时按这个顺序讲）

```
① 定义状态：dp[i] / dp[i][j] 到底表示什么？（最难也最关键，其余都是自然的）
② 推导转移：dp[i] 由哪些更小的状态推出来？（分类讨论「最后一步的选择」）
③ 确定边界：dp[0] 是多少？空集/单元素时答案是什么？
④ 确定顺序：从小到大（保证用到的状态已经算好）；空间能否压缩（滚动数组）
```

**面试口述模板（背下来）**：
> 「我用动态规划做。第一步定义状态：`dp[i]` 表示……。第二步看最后一个元素的选择，分两种情况，所以转移方程是 `dp[i] = max(dp[i-1], dp[i-2] + x)`。边界是 `dp[0] = ...`、`dp[1] = ...`。按 i 从小到大递推，答案是 `dp[n]`。时间和空间都是 O(n)，因为每步只依赖前两个状态，所以可以把空间优化到 O(1)。」

**DP 的两个判断信号**：
- **能用 DP**：有**重叠子问题**（暴力递归会重复计算）+ **最优子结构**（大问题的最优解由子问题最优解构成）。
- **不能用贪心**：局部最优推不出全局最优（比如零钱兑换的硬币面值 `[1,3,4]` 凑 6 元，贪心给 4+1+1=3 枚，最优是 3+3=2 枚）。

### 3.2 爬楼梯（DP 入门，LeetCode 70）

```go
// dp[i] = 到第 i 阶的方法数；dp[i] = dp[i-1] + dp[i-2]（最后一步走 1 阶或 2 阶）
func climbStairs(n int) int {
    if n <= 2 { return n }
    a, b := 1, 2                  // a=dp[i-2], b=dp[i-1]（滚动变量，空间 O(1)）
    for i := 3; i <= n; i++ {
        a, b = b, a+b
    }
    return b
}
```

### 3.3 打家劫舍（LeetCode 198 / 213）

```go
// 198：相邻不能都偷，求最大金额
// dp[i] = max(dp[i-1], dp[i-2]+nums[i])  偷 or 不偷第 i 家
func rob(nums []int) int {
    if len(nums) == 0 { return 0 }
    prev, cur := 0, 0             // prev = dp[i-2]，cur = dp[i-1]
    for _, v := range nums {
        prev, cur = cur, max(cur, prev+v)
    }
    return cur
}

// 213 打家劫舍 II：环形（首尾相邻）→ 拆成两个线性问题取最大
// ① 偷第一家：范围 [0, n-2]；② 不偷第一家：范围 [1, n-1]
func rob2(nums []int) int {
    n := len(nums)
    if n == 1 { return nums[0] }
    return max(rob(nums[:n-1]), rob(nums[1:]))
}
```

### 3.4 背包问题（DP 的核心母题）

#### 0-1 背包（每件物品只能选一次）

```
dp[i][j] = 前 i 件物品、容量 j 时的最大价值
转移：dp[i][j] = max(dp[i-1][j],              // 不选第 i 件
                     dp[i-1][j-w[i]] + v[i])  // 选第 i 件
```

```go
// 二维版（好理解）
func knapsack01(w, v []int, cap int) int {
    n := len(w)
    dp := make([][]int, n+1)
    for i := range dp { dp[i] = make([]int, cap+1) }
    for i := 1; i <= n; i++ {
        for j := 0; j <= cap; j++ {
            dp[i][j] = dp[i-1][j]                  // 不选
            if j >= w[i-1] {
                dp[i][j] = max(dp[i][j], dp[i-1][j-w[i-1]]+v[i-1])  // 选
            }
        }
    }
    return dp[n][cap]
}

// 一维滚动数组版（必背）：容量必须倒序遍历！
func knapsack01Rolling(w, v []int, cap int) int {
    dp := make([]int, cap+1)
    for i := 0; i < len(w); i++ {
        for j := cap; j >= w[i]; j-- {          // ← 倒序，保证 dp[j-w[i]] 是「上一轮」的值
            dp[j] = max(dp[j], dp[j-w[i]]+v[i])
        }
    }
    return dp[cap]
}
```

**为什么 0-1 背包要倒序？**（面试必问）
> 「正序会让同一件物品被重复使用——因为 `dp[j-w[i]]` 已经是**本轮**更新过的值，相当于又放了一次第 i 件物品。倒序时 `dp[j-w[i]]` 还是上一轮（未放第 i 件）的值，保证每件物品只选一次。而完全背包正序就是这个特性，正好允许重复取。」

#### 完全背包（每件物品可以选无限次）

```go
// 完全背包：容量正序遍历 → 允许重复选取
func knapsackComplete(w, v []int, cap int) int {
    dp := make([]int, cap+1)
    for i := 0; i < len(w); i++ {
        for j := w[i]; j <= cap; j++ {          // ← 正序
            dp[j] = max(dp[j], dp[j-w[i]]+v[i])
        }
    }
    return dp[cap]
}
```

**背包三兄弟的判别（这是最容易考混的）**：

| 变体 | 循环顺序 | 典型题 |
|---|---|---|
| 0-1 背包 | 物品外层，容量**倒序** | 416 分割等和子集、494 目标和 |
| 完全背包（组合数） | 物品外层，容量**正序** | 518 零钱兑换 II（求组合数） |
| 完全背包（排列数） | **容量外层**，物品内层 | 377 组合总和 IV（求排列数） |

**记忆法**：「物品在外层 → 按物品顺序考虑，是组合；容量在外层 → 每个容量都可以从头选物品，是排列。」

```go
// LeetCode 416 分割等和子集：能否分成两个等和子集 → 0-1 背包能否恰好装满 sum/2
func canPartition(nums []int) bool {
    sum := 0
    for _, v := range nums { sum += v }
    if sum%2 != 0 { return false }
    target := sum / 2
    dp := make([]bool, target+1)
    dp[0] = true
    for _, v := range nums {
        for j := target; j >= v; j-- {      // 倒序：每个数只能用一次
            dp[j] = dp[j] || dp[j-v]
        }
    }
    return dp[target]
}

// LeetCode 322 零钱兑换：凑出金额所需的最少硬币数（完全背包求最小值）
func coinChange(coins []int, amount int) int {
    const INF = 1 << 30
    dp := make([]int, amount+1)
    for i := 1; i <= amount; i++ { dp[i] = INF }
    dp[0] = 0
    for _, c := range coins {
        for j := c; j <= amount; j++ {       // 正序：硬币可重复使用
            if dp[j-c]+1 < dp[j] {
                dp[j] = dp[j-c] + 1
            }
        }
    }
    if dp[amount] == INF { return -1 }
    return dp[amount]
}
```

### 3.5 最长公共子序列（LCS，LeetCode 1143）

```
dp[i][j] = s1 前 i 个字符与 s2 前 j 个字符的 LCS 长度
转移：s1[i-1] == s2[j-1] → dp[i][j] = dp[i-1][j-1] + 1
      否则                → dp[i][j] = max(dp[i-1][j], dp[i][j-1])
```

```go
func longestCommonSubsequence(t1, t2 string) int {
    m, n := len(t1), len(t2)
    dp := make([][]int, m+1)          // 多一行一列表示「空串」，省掉边界特判
    for i := range dp { dp[i] = make([]int, n+1) }
    for i := 1; i <= m; i++ {
        for j := 1; j <= n; j++ {
            if t1[i-1] == t2[j-1] {
                dp[i][j] = dp[i-1][j-1] + 1
            } else {
                dp[i][j] = max(dp[i-1][j], dp[i][j-1])
            }
        }
    }
    return dp[m][n]
}
```

### 3.6 最长递增子序列（LIS，LeetCode 300）

```go
// 解法一：DP O(n²) —— dp[i] = 以 nums[i] 结尾的 LIS 长度
func lengthOfLIS(nums []int) int {
    if len(nums) == 0 { return 0 }
    dp := make([]int, len(nums))
    ans := 1
    for i := 0; i < len(nums); i++ {
        dp[i] = 1                          // 至少包含自己
        for j := 0; j < i; j++ {
            if nums[j] < nums[i] && dp[j]+1 > dp[i] {
                dp[i] = dp[j] + 1
            }
        }
        ans = max(ans, dp[i])
    }
    return ans
}

// 解法二：贪心 + 二分 O(n log n) —— 维护 tails[i] = 长度为 i+1 的 LIS 的最小结尾
func lengthOfLISFast(nums []int) int {
    tails := []int{}                       // tails 本身是严格递增的
    for _, v := range nums {
        // 在 tails 中找第一个 >= v 的位置
        i := sort.SearchInts(tails, v)     // 等价于 lowerBound
        if i == len(tails) {
            tails = append(tails, v)       // 比所有结尾都大 → 延长 LIS
        } else {
            tails[i] = v                   // 替换，让结尾更小（更有增长潜力）
        }
    }
    return len(tails)                      // tails 的长度就是 LIS 长度
}
```

**关键理解（口述时讲）**：`tails` 数组**不是**真实的 LIS 序列，它表示「长度为 i+1 的递增子序列能达到的最小结尾值」。结尾越小，后面越容易接上。替换操作是贪心的体现。**注意 `sort.SearchInts` 是求值序列的方法，如果要 recover 出具体序列还需要额外记录下标。**

**同类题**：354 俄罗斯套娃信封、673 最长递增子序列的个数、面试常问的「变体：最长连续序列用哈希做 O(n)」。

### 3.7 编辑距离（LeetCode 72，DP 的经典中的经典）

```
dp[i][j] = word1 前 i 个字符转成 word2 前 j 个字符的最少操作数
转移：
  相等 → dp[i][j] = dp[i-1][j-1]                        （不用操作）
  不等 → dp[i][j] = 1 + min(
            dp[i-1][j],      // 删除 word1[i-1]
            dp[i][j-1],      // 插入 word2[j-1]
            dp[i-1][j-1])    // 替换
边界：dp[i][0] = i（全删）、dp[0][j] = j（全插）
```

```go
func minDistance(w1, w2 string) int {
    m, n := len(w1), len(w2)
    dp := make([][]int, m+1)
    for i := range dp {
        dp[i] = make([]int, n+1)
        dp[i][0] = i                  // 边界：word1 前 i 个 → 空串，需要删 i 次
    }
    for j := 0; j <= n; j++ { dp[0][j] = j }

    for i := 1; i <= m; i++ {
        for j := 1; j <= n; j++ {
            if w1[i-1] == w2[j-1] {
                dp[i][j] = dp[i-1][j-1]
            } else {
                dp[i][j] = 1 + min3(dp[i-1][j], dp[i][j-1], dp[i-1][j-1])
            }
        }
    }
    return dp[m][n]
}
```

**业务映射（主动提，很加分）**：
> 「编辑距离在工程里最典型的应用是**模糊匹配**和**拼写纠错**——比如用户输入商品名搜索，允许错一两个字；
> 还有**数据去重**，判断两条客户记录是不是同一个人（姓名+地址的相似度）。
> 我们做客户数据治理时就用过类似的字符串相似度思路。」

### 3.8 最大子数组和（LeetCode 53，DP 的极简形态）

```go
// dp[i] = 以 nums[i] 结尾的最大子数组和；dp[i] = max(nums[i], dp[i-1]+nums[i])
func maxSubArray(nums []int) int {
    ans, cur := nums[0], nums[0]
    for _, v := range nums[1:] {
        cur = max(v, cur+v)      // 前面的贡献是负的，就从这个元素重新开始

    }

}
```

### 3.9 贪心 vs 动态规划（面试常拿来对比）

**贪心**：每一步都取当前最优，不回退。**能用贪心的前提是「局部最优能推出全局最优」**（需要证明或反例推翻）。

| | 贪心 | 动态规划 |
|---|---|---|
| 决策 | 每步只做一个选择，不回头 | 枚举所有可能，取最优 |
| 是否记录所有状态 | 否 | 是（dp 表） |
| 复杂度 | 通常更低（O(n) / O(n log n)） | 通常更高 |
| 正确性 | **需要证明** | 状态转移正确即可 |
| 典型题 | 455 分发饼干、435 无重叠区间、55 跳跃游戏、122 买卖股票 II、860 柠檬水找零 | 背包、编辑距离、LIS |

**经典对比题**：LeetCode 322 零钱兑换（DP）vs 860 柠檬水找零（贪心）。面试被问「这题为什么不用贪心」时，用 `coins=[1,3,4]`, `amount=6` 的反例说明。

### 3.10 回溯（DFS 的一种，模板统一）

**回溯 = 递归 + 撤销选择**。所有回溯题的模板几乎一致：

```go
func backtrack(路径, 选择列表) {
    if 满足结束条件 {
        记录结果
        return
    }
    for 选择 := range 选择列表 {
        做选择          // 路径.push(选择)
        backtrack(路径, 新的选择列表)
        撤销选择        // 路径.pop()
    }
}
```

#### 全排列（LeetCode 46）

```go
func permute(nums []int) [][]int {
    var ans [][]int
    used := make([]bool, len(nums))
    path := make([]int, 0, len(nums))

    var dfs func()
    dfs = func() {
        if len(path) == len(nums) {              // 结束条件
            ans = append(ans, append([]int(nil), path...))  // 必须拷贝！path 会被复用
            return
        }
        for i, v := range nums {
            if used[i] { continue }              // 剪枝：已用过的不能再用
            used[i] = true
            path = append(path, v)               // 做选择
            dfs()
            path = path[:len(path)-1]            // 撤销选择
            used[i] = false
        }
    }
    dfs()
    return ans
}
```

**最大的坑**：`ans = append(ans, path)` 会把切片的**引用**存进去，后续修改 path 会污染结果——**必须拷贝**（`append([]int(nil), path...)`）。这个点面试官非常爱看，主动说出来是加分项。

#### 子集（LeetCode 78）

```go
func subsets(nums []int) [][]int {
    var ans [][]int
    path := []int{}
    var dfs func(start int)
    dfs = func(start int) {
        ans = append(ans, append([]int(nil), path...))   // 每个节点都是一个子集
        for i := start; i < len(nums); i++ {             // start 保证不回头选
            path = append(path, nums[i])
            dfs(i + 1)
            path = path[:len(path)-1]
        }
    }
    dfs(0)
    return ans
}
```

#### 组合总和（LeetCode 39，可重复选取）

```go
func combinationSum(candidates []int, target int) [][]int {
    var ans [][]int
    var path []int
    var dfs func(start, remain int)
    dfs = func(start, remain int) {
        if remain == 0 {
            ans = append(ans, append([]int(nil), path...))
            return
        }
        if remain < 0 { return }                        // 剪枝
        for i := start; i < len(candidates); i++ {
            path = append(path, candidates[i])
            dfs(i, remain-candidates[i])                // 传 i（不是 i+1）：允许重复选自己
            path = path[:len(path)-1]
        }
    }
    dfs(0, target)
    return ans
}
```

#### N 皇后（LeetCode 51，回溯的终极形态，展示「剪枝」意识）

```go
func solveNQueens(n int) [][]string {
    var ans [][]string
    cols := make([]bool, n)          // 列占用
    diag1 := make([]bool, 2*n-1)     // 主对角线（r - c + n - 1 相同）
    diag2 := make([]bool, 2*n-1)     // 副对角线（r + c 相同）
    queens := make([]int, n)         // queens[r] = c

    var dfs func(r int)
    dfs = func(r int) {
        if r == n {
            board := make([]string, n)
            for i := 0; i < n; i++ {
                row := make([]byte, n)
                for j := range row { row[j] = '.' }
                row[queens[i]] = 'Q'
                board[i] = string(row)
            }
            ans = append(ans, board)
            return
        }
        for c := 0; c < n; c++ {
            d1, d2 := r-c+n-1, r+c
            if cols[c] || diag1[d1] || diag2[d2] { continue }   // O(1) 冲突检测
            cols[c], diag1[d1], diag2[d2] = true, true, true
            queens[r] = c
            dfs(r + 1)
            cols[c], diag1[d1], diag2[d2] = false, false, false  // 撤销
        }
    }
    dfs(0)
    return ans
}
```

**回溯的复杂度**：全排列 O(n·n!)、子集 O(n·2ⁿ)、N 皇后 O(n!)。**面试要点是「讲清剪枝」**——「我用三个布尔数组把冲突检测从 O(n) 降到 O(1)，剪枝后每层可选的列数急剧减少，实际运行远小于理论上界。」

**回溯 vs DFS 的区别**（口述加分）：DFS 是**图/树的遍历方式**，回溯是**在解空间树上做搜索 + 撤销**的算法思想，本质都是用递归 + 状态恢复。回溯一定会「撤销选择」，DFS 不一定。

### 5.1 快速排序（随机基准 + 三路）

```go
package main

import (
    "math/rand"
)

// 三路快排：处理大量重复元素不退化；小区间可用插入排序优化
func QuickSort(a []int) {
    quickSort(a, 0, len(a)-1)
}

func quickSort(a []int, lo, hi int) {
    if lo >= hi {
        return
    }
    pivot := a[lo+rand.Intn(hi-lo+1)]
    lt, i, gt := lo, lo, hi
    for i <= gt {
        switch {
        case a[i] < pivot:
            a[lt], a[i] = a[i], a[lt]
            lt++
            i++
        case a[i] > pivot:
            a[gt], a[i] = a[i], a[gt]
            gt--
        default:
            i++
        }
    }
    quickSort(a, lo, lt-1)
    quickSort(a, gt+1, hi)
}
```

### 5.2 堆排序

```go
func HeapSort(a []int) {
    n := len(a)
    for i := n/2 - 1; i >= 0; i-- {   // 建堆 O(n)
        sink(a, i, n)
    }
    for i := n - 1; i > 0; i-- {      // 逐个把堆顶换到末尾
        a[0], a[i] = a[i], a[0]
        sink(a, 0, i)
    }
}

func sink(a []int, i, n int) {
    for {
        l, r, largest := 2*i+1, 2*i+2, i
        if l < n && a[l] > a[largest] { largest = l }
        if r < n && a[r] > a[largest] { largest = r }
        if largest == i { return }
        a[i], a[largest] = a[largest], a[i]
        i = largest
    }
}
```

### 5.3 LRU 缓存（设计题之王，客服/后台系统真实会用）

**要求**：`Get` 和 `Put` 都是 O(1)。**结构**：哈希表（O(1) 定位）+ 双向链表（O(1) 移动/删除，且能维护访问顺序）。

```go
// 手写双向链表版本（面试推荐——能展示你对「为什么需要双向」的理解）
type node struct {
    key, val   int
    prev, next *node
}

type LRUCache struct {
    cap        int
    m          map[int]*node
    head, tail *node          // 虚拟头尾，省掉大量判空
}

func Constructor(capacity int) LRUCache {
    head, tail := &node{}, &node{}
    head.next, tail.prev = tail, head
    return LRUCache{cap: capacity, m: make(map[int]*node), head: head, tail: tail}
}

func (c *LRUCache) Get(key int) int {
    if n, ok := c.m[key]; ok {
        c.moveToFront(n)
        return n.val
    }
    return -1
}

func (c *LRUCache) Put(key, value int) {
    if n, ok := c.m[key]; ok {          // 已存在：更新值并移到最前
        n.val = value
        c.moveToFront(n)
        return
    }
    if len(c.m) == c.cap {              // 容量满：淘汰链表尾部（最久未使用）
        last := c.tail.prev
        c.remove(last)
        delete(c.m, last.key)
    }
    n := &node{key: key, val: value}
    c.m[key] = n
    c.addToFront(n)
}

func (c *LRUCache) addToFront(n *node) {
    n.prev = c.head
    n.next = c.head.next
    c.head.next.prev = n
    c.head.next = n
}

func (c *LRUCache) remove(n *node) {
    n.prev.next = n.next
    n.next.prev = n.prev
}

func (c *LRUCache) moveToFront(n *node) {
    c.remove(n)
    c.addToFront(n)
}
```

**为什么是双向链表而不是单链表？** 删除节点需要它的前驱（`n.prev.next = n.next`），单链表要 O(n) 找前驱，双向链表 O(1)。这就是「为什么 LRU 必须双向」的标准答案。

**Go 标准库版本（面试可以说明「工程里我会用标准库」）**：

```go
import "container/list"

type LRU2 struct {
    cap   int
    m     map[int]*list.Element
    l     *list.List          // Front = 最近使用，Back = 最久未使用
}
type entry struct{ k, v int }

func (c *LRU2) Get(key int) int {
    if e, ok := c.m[key]; ok {
        c.l.MoveToFront(e)
        return e.Value.(entry).v
    }
    return -1
}
func (c *LRU2) Put(key, value int) {
    if e, ok := c.m[key]; ok {
        e.Value = entry{key, value}
        c.l.MoveToFront(e)
        return
    }
    if c.l.Len() >= c.cap {
        back := c.l.Back()
        c.l.Remove(back)
        delete(c.m, back.Value.(entry).k)
    }
    c.m[key] = c.l.PushFront(entry{key, value})
}
```

> **话术提示**：「LRU 我在数据中台项目里实际用过——商品档案和门店信息这类变更不频繁的数据，本地缓存一层减少数据库压力，缓存容量有限就用了 LRU 淘汰策略。所以「为什么用哈希 + 双向链表」我不只是背的，是算过复杂度的。」

### 5.4 生产者-消费者（Go 并发手写题，岗位大概率会考）

```go
package main

import (
    "context"
    "fmt"
    "sync"
    "time"
)

// 场景：N 个生产者往队列投递任务，M 个消费者处理
func main() {
    const (
        producerN = 3
        consumerN = 5
        taskN     = 20
        queueSize = 10
    )
    ch := make(chan int, queueSize)
    ctx, cancel := context.WithCancel(context.Background())
    var wgProducer, wgConsumer sync.WaitGroup

    // 生产者
    for p := 0; p < producerN; p++ {
        wgProducer.Add(1)
        go func(id int) {
            defer wgProducer.Done()
            for i := 0; i < taskN/producerN+1; i++ {
                select {
                case ch <- id*100 + i:          // 队列满时阻塞（天然背压）
                case <-ctx.Done():              // 支持取消，避免 goroutine 泄漏
                    return
                }
            }
        }(p)
    }

    // 消费者
    for c := 0; c < consumerN; c++ {
        wgConsumer.Add(1)
        go func(id int) {
            defer wgConsumer.Done()
            for {
                select {
                case task, ok := <-ch:
                    if !ok { return }           // channel 已关闭且取空
                    fmt.Printf("消费者 %d 处理任务 %d\n", id, task)
                    time.Sleep(10 * time.Millisecond)
                case <-ctx.Done():
                    return
                }
            }
        }(c)
    }

    // 关键顺序：生产者结束 → 关闭 channel → 消费者因 ok=false 退出
    wgProducer.Wait()
    close(ch)                                   // 只有发送方关闭 channel！
    wgConsumer.Wait()
    cancel()
}
```

**面试要说明的四个点（主动讲，显得有工程经验）**：
1. **channel 由谁关闭**：只有发送方（生产者）在「所有发送完成后」关闭；接收方不能关闭，否则 panic。
2. **`select` + `ctx.Done()`**：让生产/消费都能被取消，避免 goroutine 泄漏（这比死循环更专业）。
3. **缓冲 channel 是背压手段**：队列满时生产者阻塞，天然限流；也可以用信号量 `chan struct{}` 或 `errgroup.SetLimit`。
4. **关闭顺序**：先 `wgProducer.Wait()` → `close(ch)` → `wgConsumer.Wait()`，三步顺序错了会 panic 或卡死。

### 5.5 单例（Go 的正确写法）

```go
import (
    "sync"
    "sync/atomic"
)

// ✅ 推荐：sync.Once（Go 官方推荐，一次就够了）
type Config struct {
    DSN string
}

var (
    configOnce sync.Once
    configInst *Config
)

func GetConfig() *Config {
    configOnce.Do(func() {
        configInst = &Config{DSN: "mysql://..."}   // 初始化只执行一次，且并发安全
    })
    return configInst
}
```

```go
// ❌ 双检锁在 Go 里是反模式（不要这样写！）
var mu sync.Mutex
var inst *Config
func Bad() *Config {
    if inst == nil {            // 这里的读没有同步保护，可能拿到「部分构造」的对象
        mu.Lock()
        defer mu.Unlock()
        if inst == nil {
            inst = &Config{}
        }
    }
    return inst
}
```

**面试标准答法**：
> 「Go 里实现单例最推荐 `sync.Once`，它内部用原子操作 + 互斥锁保证初始化只执行一次，而且**返回时的内存可见性由 `Do` 内部的内存屏障保证**，所以不会出现 Java 里那种「指令重排导致拿到半初始化对象」的问题——Go 的内存模型下 `Do` 返回即代表之前的写入对后续 goroutine 可见。所以 Go 里**不需要双检锁**，写了反而是坏味道。如果需要懒加载 + 更高性能，也可以用 `atomic.Pointer` 做无锁读。」

### 5.6 反转链表 / 层序遍历 / 二分（速查版）

```go
// ① 反转链表
func reverseList(head *ListNode) *ListNode {
    var pre *ListNode
    for cur := head; cur != nil; {
        nxt := cur.Next
        cur.Next = pre
        pre, cur = cur, nxt
    }
    return pre
}

// ② 层序遍历（按层返回）
func levelOrder(root *TreeNode) [][]int {
    if root == nil { return nil }
    var res [][]int
    q := []*TreeNode{root}
    for len(q) > 0 {
        size := len(q)
        level := make([]int, 0, size)
        for i := 0; i < size; i++ {
            n := q[0]; q = q[1:]
            level = append(level, n.Val)
            if n.Left != nil  { q = append(q, n.Left) }
            if n.Right != nil { q = append(q, n.Right) }
        }
        res = append(res, level)
    }
    return res
}

// ③ 二分查找（左闭右开，返回第一个 >= target 的下标）
func lowerBound(nums []int, target int) int {
    lo, hi := 0, len(nums)
    for lo < hi {
        mid := lo + (hi-lo)/2
        if nums[mid] < target {
            lo = mid + 1
        } else {
            hi = mid
        }
    }
    return lo
}
```

## 六、算法口述技巧（面试官不开编辑器时怎么办）

### 6.1 讲思路的四步法（暴力 → 优化 → 复杂度 → 边界）

拿到题后**不要立刻写代码**，按这个顺序说（面试官会认为你是有方法论的工程师）：

```
第 1 步：确认题意（30 秒）
  「我先确认一下：输入是……，输出是……，数据范围是多大？有没有重复元素？要不要考虑空输入？」

第 2 步：先说暴力解（重要！先有解再优化）
  「最直接的做法是两层循环枚举所有组合，时间复杂度 O(n²)，空间 O(1)。」
  —— 说暴力解不是浪费，是为了：(a) 让自己想清楚问题，(b) 让面试官看到你的思路起点。

第 3 步：找瓶颈再优化
  「瓶颈在于每次都要重新扫描，如果能用哈希表把『查找』降到 O(1)，整体就是 O(n)。」
  —— 优化方向就这么几类，背下来就不慌：
     · 空间换时间：哈希表、前缀和、缓存
     · 有序性：排序后双指针 / 二分
     · 单调性：单调栈、单调队列、滑动窗口
     · 重叠子问题：记忆化 → DP
     · 剪枝：回溯时提前排除不可能的分支

第 4 步：说复杂度 + 边界
  「时间是 O(n)，空间是 O(n)（哈希表最坏情况）。边界上要处理空数组、长度为 1、以及全部元素相同的情况。」
```

### 6.2 复杂度分析怎么说才专业

- **时间**：说出「主要操作的执行次数」，不要只说结论。例：「外层遍历 n 次，内层每次最多比较常数次，所以是 O(n)」。
- **空间**：区分「额外空间」和「总空间」。递归要算**递归栈深度**。例：「我用了额外的哈希表，空间 O(n)；递归深度最多 h，所以栈空间 O(h)」。
- **均摊分析**：说 append / 哈希扩容时用「均摊 O(1)」，能体现你理解背后的机制。
- **常见陷阱**：不要漏掉排序的 O(n log n)（比如三数之和总体是 O(n²)，排序不主导）；字符串拼接在 Go 里用 `+=` 是 O(n²)，要用 `strings.Builder`。

### 6.3 没思路时的应对（不要沉默！）

**四句可以直接用的话**：

1. **复述 + 举例**：「我先用一个小例子手动推一下……」（画小例子往往能看出规律）
2. **缩小规模**：「如果数组只有一个元素，答案是什么？两个呢？」（找递推关系 = DP 的雏形）
3. **换视角提问**：「这题是要我找最优解还是任意解？如果允许 O(n log n) 我可以用排序 + 二分。」
4. **要提示**：「我目前想到的是用哈希表把查找降到 O(1)，但处理重复元素这里还没想清楚，能给一点提示吗？」
   —— **要提示不丢分，沉默 5 分钟才丢分**。面试官更看重沟通能力。

**保底策略（真的写不出最优解时）**：
- 先写能跑通的暴力解，把代码写完整、边界处理好，然后说明优化方向：「暴力解我先写出来保证正确性，优化方向是把内层查找换成哈希表，可以把 O(n²) 降到 O(n)，您希望我继续写优化版吗？」
- **能跑通的暴力解 > 写了一半的最优解**。这一点在工程岗位的面试里尤其成立。

### 6.4 手写代码时的加分细节

1. **命名清晰**：`lo/hi/mid/tmp/prev/cur/nxt`，别用 `i/j/k` 混到底。
2. **边写边说**：写 `nxt := cur.Next` 时说「这里先保存下一个节点，否则改指针后就找不到了」。
3. **主动处理边界**：写完立刻说「这里我加了 `if root == nil` 的判断，避免空指针」。
4. **Go 语言细节体现熟练度**：用 `max`/`min`（Go 1.21+ 内置）、哑结点技巧、`make([]int, 0, n)` 预分配、`switch` 代替长 `if-else`、错误处理用 `if err != nil`。
5. **写完自测**：手动跑一个 3~5 个元素的小例子，说出每一步的状态变化。

### 6.5 把算法题接到业务上（岗位差异化的关键）

面试官问「你平时怎么用这些算法」时，用这些真实的映射回答（都是客服/OA/后台场景）：

| 算法 | 业务场景 |
|---|---|
| LRU | 接口缓存、字典数据缓存、会话缓存 |
| TopK + 小顶堆 | 热门工单排行、接口调用量 Top10、商品销量榜 |
| 哈希计数 | UV 统计、错误码分布、去重 |
| 滑动窗口 | 限流（固定窗口/滑动窗口）、近期消息统计 |
| 单调栈 | 股票/价格类的「下一个更高」、柱状图最大面积（看板图表） |
| 拓扑排序 | **审批流依赖、任务调度 DAG、微服务启动依赖** |
| 二分答案 | 分库分表数量、限流阈值、批量任务批次大小 |
| 回溯 | 菜单树/组织树展开、权限组合、工单流转路径枚举 |
| 区间合并 | **排班时间段合并、工单处理时段统计、可用工单池** |
| 编辑距离 | 客户名称模糊匹配、数据去重、搜索纠错 |

> **话术模板**：
> 「我平时刷题不多，但我更在意算法在业务里的落点。比如**区间合并**，我在做排班和工单统计时就用过——
> 一天里多个时间段的处理记录需要合并成连续时段，先按开始时间排序再线性合并，O(n log n) 排序 + O(n) 合并，
> 比用 SQL 硬算或者全量比对清晰得多。**拓扑排序**在 OA 审批流里也很直接——节点依赖关系就是一张有向图，
> 能不能走通就是有没有环。」
