# 05｜微服务、数据库与中间件

## gRPC

Protobuf 字段号只增不改，保留废弃字段号；RPC 设置 deadline 并透传 context；区分业务错误与可重试基础设施错误。重试必须满足幂等或携带幂等键，避免重复扣费/创建。拦截器适合统一鉴权、日志、trace 和指标。

## Redis

缓存模式常用 Cache Aside：读未命中查库并回填，写操作更新数据库后删除缓存。穿透用参数校验、空值缓存或布隆过滤器；击穿可用互斥重建/逻辑过期；雪崩通过 TTL 打散、限流和降级处理。分布式锁要有唯一 token、过期和续约语义，不能把它当数据库事务替代品。

## MySQL

索引服务于查询条件、排序和覆盖读取；用 `EXPLAIN` 看实际执行计划。事务隔离、锁范围和死锁需要结合 SQL 讲；大分页尽量用基于索引的游标/seek 分页。对计费、消费等不可重复副作用，唯一键和状态机通常比“先查后写”可靠。

## RabbitMQ

RabbitMQ 通常提供至少一次语义：成功处理后 ack，消费者天然需要幂等。失败按可恢复性重试，达到阈值进死信；监控队列长度、消费速率、消息年龄、失败率。顺序只在单队列/单 key 局部可控，扩容与严格全局顺序不可兼得。

## 最终一致性

跨数据库与消息系统时，业务事务内写业务数据和 Outbox 事件，后台可靠投递事件；消费者幂等执行。这避免了“库写成功但消息丢失”或两阶段事务的高复杂度。需要补偿时设计可重试、可观测的状态机。
