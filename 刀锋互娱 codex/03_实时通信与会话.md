# 03｜实时通信与会话

## SSE 与 WebSocket

SSE 是服务端单向推送，基于 HTTP，适合 LLM token 流；客户端需要发控制消息或语音双向流、打断、状态同步时，WebSocket 更适合。选型看交互方向与基础设施，不是“WebSocket 一定更实时”。

## WebSocket 生命周期

1. HTTP Upgrade 前鉴权、Origin 校验、连接和用户限额。
2. 连接建立后心跳与 read/write deadline，读写通常分别由单 goroutine 管理。
3. 每条业务消息含 `messageId`、会话 ID、序号；服务端验证并幂等处理。
4. 断连后客户端指数退避重连，并携带上次确认序号；服务端按需补发或重建状态。
5. 关闭时取消 Agent context，释放计时器和通话资源。

## 流式 Agent 输出

不要将每个 token 都直接写入网络：可按时间片或 token 数合并，降低帧数；首包尽快发出；使用明确事件类型，如 `delta`、`tool_call`、`final`、`error`。客户端断开时调用 cancel，使模型 HTTP 请求和后续 goroutine 一同退出。

## IM 回调

外部 IM 通常是至少一次投递，可能重复、延迟或乱序。处理方式：用平台消息 ID/业务 ID 作为幂等键；关键操作采用唯一索引或 Redis 原子占位；按会话序号检测过旧消息；成功后记录结果。对“数据库已提交、消息未发送”使用 Outbox 表和后台投递，最终一致而非分布式事务。

## 分布式会话路由

短会话可无状态化，让任意实例从 Redis/DB 恢复状态；长连接需要连接注册表或网关粘性路由。跨节点向某连接推送，可用 Redis Pub/Sub、MQ 或网关通道。必须考虑实例下线：心跳/TTL 清理旧映射，连接归属可重建。
