# Vue 与可视化｜25 分钟

用时：阅读 15 分钟，结合实际页面复述 10 分钟。与综合设计合计 40 分钟。

## 1. 先划分状态

| 场景 | 放在哪里 | 原因 |
|---|---|---|
| 收入转成展示文字 | computed | 从已有数据派生，避免重复存储 |
| 筛选变化后重新查询 | watch | 执行异步副作用 |
| 单张图 loading、弹窗 | 组件内部 | 生命周期局部 |
| 多页面共享租户/筛选 | Pinia | 集中管理共享状态 |

ref 可包装基础值和对象，脚本通过 `.value` 访问；reactive 用于对象，直接解构基础类型属性可能丢失响应式关联。

Pinia 的 state 保存数据、getter 表达派生值、action 执行操作；解构响应式状态可使用 storeToRefs，action 可直接解构。[Pinia 官方概念](https://pinia.vuejs.org/core-concepts/)

筛选需要分享或刷新恢复时可同步 URL。退出登录、切换租户时清理旧结果，不能把其他租户数据留在页面。

## 2. 请求竞态：防抖还不够

例：先查 A，再查 B；B 先返回、A 后返回，如果都写页面，最终会显示 A 的旧数据。

处理流程：筛选变化 → 取消旧请求 → 给新请求编号 → 只有最新编号可以更新结果、错误及 loading。防抖仅减少请求数量，不能保证响应顺序。

多张图应关联同一筛选快照；部分成功时明确展示哪些图失败，避免新旧口径混杂。

## 3. 图表生命周期

容器有尺寸后初始化 ECharts，查询完成更新数据；容器尺寸变化时调用 resize，组件卸载时 dispose 并清理监听。仅监听窗口变化可能漏掉侧栏展开等容器变化。[ECharts 容器说明](https://echarts.apache.org/handbook/en/concepts/chart-size/)

大量数据先按展示粒度聚合，比如月趋势按天展示；明细表用分页或虚拟滚动。不要把所有原始事件都送到浏览器。

## 4. 页面必须处理的四种状态

- 加载：显示反馈，旧数据若保留要明确标识正在刷新。
- 空数据：与请求失败区分。
- 错误：可重试，但避免无上限自动重试。
- 数据过期：展示更新时间或延迟状态。

Vite 只需记住：开发代理不代替生产路由/跨域配置；浏览器能拿到的配置不能存密码或私钥。

## 面试答法与自测

“我把筛选、查询和展示分开，共享状态放 Pinia，派生值用 computed。请求用取消加编号避免旧结果覆盖，图表实例复用并在卸载时释放。”

选一个商云前台真实页面，讲清组件、状态、接口和一个错误场景。没用过 Pinia 或 ECharts，就把上述内容表述为理解或方案。
